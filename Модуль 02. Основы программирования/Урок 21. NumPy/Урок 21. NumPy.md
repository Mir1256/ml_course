## 1. Зачем это нужно

- **Скорость.** Векторизованный код быстрее Python-циклов в десятки и сотни раз. В коде урока IoU-матрица 300×500 ускорилась в 39 раз. Для попарных расстояний эмбеддингов, NMS, метрик и аугментаций это разница между «секунды» и «часы».
- **Корректность.** Самые коварные баги в CV-коде — с осями и памятью: перепутанные HWC/CHW, `reshape` вместо `transpose`, неожиданный broadcasting, изменение view, которое портит исходный массив, переполнение `uint8`.
- **Чтение чужого кода.** Код attention, функций потерь и метрик в репозиториях моделей написан на einsum, fancy indexing и broadcasting.

## 2. Интуиция: ndarray = буфер + «очки» для чтения

Массив NumPy — это **непрерывный кусок памяти** плюс метаданные: `dtype` (как читать байты), `shape` (форма) и `strides` (на сколько байт прыгать, чтобы сдвинуться на 1 вдоль каждой оси).

Многие операции не трогают данные, а только меняют «очки», через которые на них смотрят. Это **view** (представление): срезы, `transpose`, `reshape` (когда возможно), `sliding_window_view`. Они бесплатны: $O(1)$ памяти и времени. Но изменение view меняет исходный массив.

Другие операции обязаны собрать новые данные. Это **copy**: fancy indexing (по массиву индексов), булевы маски, арифметика, `reshape` несмежного массива.

**Broadcasting** — договорённость, как совмещать массивы разной формы без копирования: недостающие оси и оси длины 1 «растягиваются».

## 3. Математика модели памяти

### 3.1. Адресация через strides

Элемент с индексами $(i_0, \dots, i_{d-1})$ лежит по адресу

$$\text{addr} = \text{base} + \sum_k i_k\cdot\text{stride}_k.$$

Для C-порядка (последняя ось меняется быстрее всего) $\text{stride}_{d-1} = \text{itemsize}$, $\text{stride}_k = \text{stride}_{k+1}\cdot\text{shape}_{k+1}$. У картинки `(480, 640, 3)` uint8 strides `(1920, 3, 1)`: строка = 640·3 байт.

- **Транспонирование** просто переставляет `shape` и `strides`: `(3, 480, 640)` со strides `(1, 1920, 3)`. Данные не двигались, но массив перестал быть C-смежным (contiguous). Операции по последней оси на нём медленнее (прыжки по памяти, промахи кэша). `torch.from_numpy` и многие C-библиотеки требуют смежности — отсюда `np.ascontiguousarray` / `tensor.contiguous()`.
- **Срез с шагом** `a[::2]` умножает stride на 2, `a[::-1]` делает его отрицательным.
- **`reshape` — view, только если** новая форма достижима «переразбиением» тех же strides. Для смежного массива это всегда так. Для транспонированного — обычно нет, и `reshape` молча делает копию (в PyTorch `view()` в этом случае бросает ошибку, а `reshape()` копирует).

### 3.2. Правила broadcasting

Формы выравниваются **по правому краю**. Для каждой оси размеры должны быть равны, либо один из них равен 1 (тогда он «растягивается»). Недостающие слева оси считаются равными 1. Растягивание — это stride 0: память не копируется.

| A | B | Результат |
|---|---|---|
| `(8, 3, 32, 32)` | `(3, 1, 1)` | `(8, 3, 32, 32)` ✓ |
| `(8, 3, 32, 32)` | `(3,)` | ✗ — сравнивается с последней осью 32 |
| `(n, 1, 4)` | `(1, m, 4)` | `(n, m, 4)` — все пары: так строятся попарные IoU и расстояния |

### 3.3. einsum: запись через индексы

`np.einsum("bqd,bkd->bqk", Q, K)` означает $S_{bqk} = \sum_d Q_{bqd}K_{bkd}$. Правила: индексы, отсутствующие в выходе, суммируются; повторённые в выходе — сохраняются. Так одной строкой записываются батчевое матричное умножение, attention-скоры $QK^\top$ (урок 83), след (`"ii->"`), внешнее произведение (`"i,j->ij"`), билинейные формы $x^\top Ay$ (`"i,ij,j->"`).

## 4. Реализация: восемь блоков урока

Файл: [код/numpy_deep.py](код/numpy_deep.py). Ключевой фрагмент — попарные IoU через broadcasting (обобщение `box_iou` из урока 11):

```python
def iou_matrix(A, B):
    """(n,4) x (m,4) -> (n,m). A[:, None] имеет форму (n,1,4), B[None] — (1,m,4)."""
    lt = np.maximum(A[:, None, :2], B[None, :, :2])
    rb = np.minimum(A[:, None, 2:], B[None, :, 2:])
    inter = np.clip(rb - lt, 0, None).prod(axis=2)
    area = lambda b: (b[:, 2] - b[:, 0]) * (b[:, 3] - b[:, 1])
    return inter / (area(A)[:, None] + area(B)[None, :] - inter)
```

Вывод (сокращён):

```
HWC strides: (1920, 3, 1) <- шаг в байтах вдоль каждой оси
после transpose -> CHW: shape (3, 480, 640) strides (1, 1920, 3) | C-contiguous: False
a[1:, ::2] (срез)                view: True
a.T (транспонирование)           view: True
a.reshape(4, 3)                  view: True
a[[0, 2]] (fancy)                view: False
a[a > 5] (маска)                 view: False
a.T.reshape(-1) (не-contiguous)  view: False

ошибка broadcasting: operands could not be broadcast together with shapes (8,3,32,32) (3,)

IoU 300x500: циклы 0.29 с, векторизация 7.5 мс, ускорение x39, совпадают: True

подсчёт классов: a[idx] += 1 -> [1 1 1 1] | np.add.at -> [1 2 1 1] | bincount -> [1 2 1 1]

einsum attention scores: (2, 6, 6) == Q @ K^T: True

uint8: 250 + 10 = 4 (переполнение по модулю 256) | через int16: 260
сумма 10^7 раз 0.1 в float32: np.sum 1000000.1 (попарное суммирование), cumsum[-1] 1087937.0 (последовательное)
```

Четыре вещи, которые стоит запомнить:
1. **`a[idx] += 1` с повторяющимися индексами** прибавляет только один раз (класс 1 встретился дважды, а счётчик — 1). Это буферизованная операция: «прочитать все → прибавить → записать все». Для накопления (гистограммы, scatter-add в градиентах) — `np.add.at` или `np.bincount`.
2. **`reshape` транспонированного массива — копия**. Об этом не предупреждают, но это важно для памяти и для того, будут ли изменения видны в оригинале.
3. **Переполнение `uint8` молчаливое**: 250 + 10 = 4. Любая арифметика над картинками — после `astype(np.float32)`.
4. **Порядок суммирования в float32 важен**: последовательная сумма 10⁷ значений 0,1 ошиблась на 9%. `np.sum` использует попарное суммирование и почти точна. При накоплении статистик по датасету это тот самый эффект из задания 🟡 урока 14.

## 5. Сверка с PyTorch: та же модель памяти

| NumPy | PyTorch | Замечание |
|---|---|---|
| `a.strides` (в байтах) | `t.stride()` (в **элементах**) | |
| `a.transpose(2, 0, 1)` | `t.permute(2, 0, 1)` | view в обоих |
| `a.reshape(...)` | `t.reshape(...)` / `t.view(...)` | `view` бросает ошибку на несмежном тензоре вместо тихой копии |
| `np.ascontiguousarray(a)` | `t.contiguous()` | |
| `np.shares_memory(a, b)` | `a.data_ptr() == b.data_ptr()` (грубо) | |
| `np.add.at(a, idx, v)` | `t.index_add_(0, idx, v)` / `scatter_add_` | на GPU недетерминированы (урок 2, задание 🔴) |
| `np.einsum` | `torch.einsum` | тот же синтаксис |
| `a[None]`, `a[:, None]` | `t.unsqueeze(0)`, `t[:, None]` | |

`torch.from_numpy(a)` создаёт тензор **на той же памяти**: изменение одного видно в другом. Поэтому отрицательные strides (`a[:, ::-1]`) torch не принимает, и после отражения картинки нужен `.copy()` (урок 20).

## 6. Типичные ошибки и как их отлаживать

| Ошибка | Симптом | Как правильно |
|---|---|---|
| `reshape` вместо `transpose` для HWC → CHW | Каша из пикселей, ошибки нет | `transpose`/`permute`; тест на маленьком массиве |
| Изменение view портит оригинал | «Аугментация испортила исходные данные» | `.copy()` там, где нужна независимость |
| Неожиданный broadcasting | `(n,)` против `(n, 1)` → матрица `(n, n)` вместо вектора | `assert x.shape == ...`; `keepdims=True` |
| `a[idx] += v` с повторами | Недосчёт | `np.add.at`, `np.bincount` |
| Арифметика в `uint8` | Переполнение по модулю 256 | `astype(np.float32)` до арифметики |
| Python-цикл по пикселям или объектам | Минуты вместо миллисекунд | Broadcasting, маски, `einsum`, `sliding_window_view` |
| Огромный промежуточный массив при broadcasting | `(n, m, 4)` для $n = m = 10^5$ → 320 ГБ, `MemoryError` | Обработка кусками (урок 3, 🔴) |
| `np.random.seed` + глобальное состояние | Невоспроизводимость между модулями | `rng = np.random.default_rng(seed)` и передача `rng` явно |

## Ответы на вопросы для самопроверки

1. Шаг в байтах вдоль каждой оси; $\text{addr} = \text{base} + \sum_k i_k\,\text{stride}_k$. При транспонировании `shape` и `strides` переставляются, данные не трогаются, массив перестаёт быть C-смежным.
2. View: базовые срезы, `transpose`/`.T`, `reshape` смежного массива, `sliding_window_view`, `np.newaxis`. Копия: fancy indexing, булевы маски, арифметика, `reshape` несмежного массива (когда новую форму нельзя выразить через strides), `ascontiguousarray` несмежного массива.
3. Выравнивание по правому краю; размеры равны или один из них 1; отсутствующие слева оси считаются 1. `(3,)` сравнивается с последней осью 32 — несовпадение. Исправление: `mean[:, None, None]` (форма `(3, 1, 1)`) или `mean.reshape(1, 3, 1, 1)`.
4. `a[idx] += 1` — это `a[idx] = a[idx] + 1`: значения читаются один раз, и для повторяющегося индекса запись происходит с одним и тем же результатом. Замена — `np.add.at(a, idx, 1)` или `np.bincount(idx, minlength=K)`.
5. `"bqd,bkd->bqk"`; `"ii->"`; `"i,ij,j->"`.
6. Отрицательный stride; тензоры PyTorch его не поддерживают. Нужна копия: `img[:, ::-1].copy()`.
7. Последовательное накопление в float32 теряет младшие разряды, когда частичная сумма становится намного больше слагаемых (ошибка растёт с $n$). `np.sum` суммирует попарно (по дереву), и ошибка растёт как $O(\log n)$.
