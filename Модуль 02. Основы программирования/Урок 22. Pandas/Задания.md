# Задания к уроку 22. Pandas

Урок: [Урок 22. Pandas.md](Урок%2022.%20Pandas.md) · код урока: [код/](код/)

Решения клади в папку [решения/](решения/) рядом с этим файлом и пиши «проверь урок 22». Требование ко всем заданиям: никаких `iterrows` и `apply(axis=1)`, никакого цепочечного присваивания.

**🟢 Базовое — «Отчёт QA по разметке»** (`qa_report.py` + `test_qa_report.py`)
На данных `make_coco_like()` из урока:
1. Найди: рамки за пределами кадра; рамки площадью < 4 px²; точные дубликаты (одинаковые картинка, класс и координаты); картинки с > 20 объектами; `iscrowd`-объекты.
2. Собери одну таблицу проблем со столбцами `ann_id`, `image_id`, `problem` (`pd.concat` нескольких выборок).
3. Сводка: число проблем по типам и топ-10 картинок по числу проблем.
4. Тесты на маленьком вручную составленном COCO-словаре, где каждая проблема встречается ровно один раз.

**🟡 Среднее — «Сопоставление предсказаний с разметкой»** (`match.py` + `test_match.py`)
Сгенерируй таблицу предсказаний: для части истинных рамок — сдвинутые копии с уверенностью, плюс ложные срабатывания.
1. Для каждой картинки сопоставь предсказания с истинными рамками одного класса по IoU ≥ 0,5. Используй merge по `(image_id, category_id)` (декартово произведение внутри картинки и класса) и векторизованный IoU по колонкам.
2. Жадно по убыванию уверенности: каждая истинная рамка может быть сопоставлена максимум один раз (`sort_values` + `drop_duplicates` в правильном порядке — подумай, в каком).
3. Посчитай TP, FP, FN по классам и precision/recall при пороге уверенности 0,5. Pivot по размерам small/medium/large.
4. Тест: на ручном примере из 3 картинок результаты совпадают с ручным подсчётом.

**🔴 Со звёздочкой — «Большие аннотации: память и скорость»** (`scale.py` + таблица замеров)
1. Сгенерируй COCO-подобные данные на 1 млн аннотаций. Замерь память DataFrame (`memory_usage(deep=True)`) при разных типах: `float64` против `float32`, `str` против `category` для класса и имени файла.
2. Сохрани в CSV, JSON (records), Parquet (snappy и zstd) и Feather. Замерь размер файла и время записи/чтения; для Parquet — чтение только 3 колонок.
3. Сравни скорость `groupby(...).agg` для ключа `str` и `category`, а также `observed=True/False`.
4. Попробуй тот же отчёт из 🟢 на **Polars** (`pip install polars`) с ленивым API (`scan_parquet` → `group_by` → `collect`). Сравни время и объясни, откуда выигрыш (многопоточность, ленивый план, Arrow).
