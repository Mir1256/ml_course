## 1. Зачем это нужно

Аннотации COCO — это JSON с тремя списками: `images`, `annotations`, `categories`. Разметка из CVAT, предсказания модели и метрики по картинкам — тоже таблицы. Всё, что ты делаешь при QA разметки, — табличные операции:
- найти картинки без разметки (anti-join);
- посчитать распределение классов и размеров (groupby);
- сопоставить предсказания с разметкой (merge);
- сделать таблицу «класс × размер» (pivot).

В pandas это строка-две. В Python-циклах — экран кода и ошибки.

## 2. Интуиция

**DataFrame** — набор колонок одинаковой длины. Каждая колонка — массив NumPy (или Arrow) одного типа, плюс общий **индекс** — метки строк. Индекс выравнивает данные при операциях, как ключ в базе. Мысли **колонками**, а не строками: `df.w * df.h` — одна векторная операция; `for _, row in df.iterrows()` — медленно, так делать не надо.

**Split–apply–combine** (`groupby`): разбей строки на группы по ключу → примени функцию к каждой → собери результат. Это `GROUP BY` из SQL.

**merge** — это `JOIN` из SQL: таблица аннотаций + таблица категорий по `category_id`.

**Copy-on-Write (CoW)** в pandas 3: любая выборка (`df[mask]`, `df["col"]`) ведёт себя как **независимая копия**. Физически данные копируются лениво — только при первой записи. Изменить исходный DataFrame можно **только** через него самого: `df.loc[mask, "col"] = ...`.

## 3. Как это устроено (вместо математики)

### 3.1. Copy-on-Write и цепочечное присваивание

В pandas 1–2 выражение `df["w"][mask] = 0` иногда меняло `df` (если `df["w"]` оказывался view), а иногда нет (если копией). Отсюда знаменитый `SettingWithCopyWarning`. В pandas 3 правило одно: **цепочечное присваивание никогда не меняет исходник** и выдаёт `ChainedAssignmentError`. В коде урока это проверено.

```python
df["w"][df.out_of_frame] = 0                     # НЕ работает в pandas 3 (и выдаёт предупреждение)
df.loc[df.out_of_frame, "w"] = 0                  # работает: одна операция над самим df
```

Выигрыш CoW — не только предсказуемость, но и память: `df2 = df[cols]` больше не копирует данные сразу.

### 3.2. Типы данных и память

| Тип | Когда | Память на значение |
|---|---|---|
| `int64`, `float64` | Числа | 8 байт |
| `float32` | Координаты, если нужна экономия | 4 байта |
| `str` (pandas 3 по умолчанию; Arrow при наличии `pyarrow`) | Произвольные строки | Компактнее старого `object` |
| `category` | Мало уникальных значений (класс, камера, разметчик) | Код (1–2 байта) + словарь уникальных значений |
| `bool` | Флаги | 1 байт |

Колонка `category` на 6000 строк заняла 6 КБ вместо 79 КБ у строк. Кроме памяти, `category` ускоряет `groupby` и задаёт порядок значений (например, small < medium < large).

### 3.3. Как устроен groupby

`groupby` — это три шага:
1. **Факторизация ключей:** каждой строке — номер группы (`np.unique(..., return_inverse=True)`).
2. **Агрегация по номерам:** для суммы и среднего — `np.bincount(inverse, weights=values)`, то есть $O(n)$. Для медианы — сортировка внутри групп, $O(n\log n)$.
3. **Сборка результата** с уникальными ключами в индексе.

Файл [код/groupby_numpy.py](код/groupby_numpy.py) реализует это с нуля и сверяет с pandas на 2 млн строк.

## 4. Реализация: COCO → таблицы → отчёты

Файл: [код/coco_tables.py](код/coco_tables.py) генерирует COCO-подобный JSON (2000 картинок, ≈ 6000 рамок) и проходит весь путь:

```python
anns[["x", "y", "w", "h"]] = pd.DataFrame(anns["bbox"].tolist(), index=anns.index)   # список -> 4 колонки

df = (anns
      .merge(cats.rename(columns={"id": "category_id", "name": "category"}), on="category_id", how="left", validate="many_to_one")
      .merge(images.rename(columns={"id": "image_id"}), on="image_id", how="left", validate="many_to_one"))

df = (df
      .assign(area=lambda d: d.w * d.h,
              rel_area=lambda d: d.w * d.h / (d.width * d.height),
              size=lambda d: pd.cut(d.w * d.h, [0, 32**2, 96**2, np.inf], labels=["small", "medium", "large"], right=False),
              out_of_frame=lambda d: (d.x + d.w > d.width) | (d.y + d.h > d.height))
      .astype({"category": "category", "supercategory": "category"}))

per_class = (df.groupby("category", observed=True)
               .agg(n=("id", "size"), images=("image_id", "nunique"), median_area=("area", "median"),
                    small_share=("size", lambda s: (s == "small").mean()))
               .sort_values("n", ascending=False))
```

Вывод (сокращён):

```

dtype строковой колонки (pandas 3: новый str-dtype): str

              n  images  median_area  small_share
category
person    3304    1653     1969.595        0.285
car       1237     934     2025.600        0.270
...
картинок без объектов: 83 из 2000
цепочечное присваивание изменило df? False | предупреждение: ChainedAssignmentError

память колонки category: str 79 КБ, category 6 КБ
Parquet 264 КБ против JSON 746 КБ; dtype category сохранился: True
```

Детали, на которые стоит обратить внимание:
- **`validate="many_to_one"`** в merge проверяет, что ключ справа уникален. Если в `categories` случайно окажется дубль id, merge молча размножит строки аннотаций, и все счётчики станут неверными. `validate` превращает тихую ошибку в громкую (тест `test_merge_validate_catches_duplicate_keys`).
- **Method chaining** (`assign`, `pipe`, `query`) — читаемая цепочка преобразований без промежуточных переменных. Лямбда в `assign` получает **текущий** DataFrame цепочки.
- **`observed=True`** в `groupby` по категориальной колонке выводит только реально встречающиеся категории.
- **Anti-join через `indicator=True`**: `_merge == "left_only"` — картинки, у которых нет ни одной аннотации. Теоретически их ≈ $e^{-3} \approx 5\%$ (число объектов ~ Пуассон(3), урок 15), получилось 83 из 2000 ≈ 4%.
- **Parquet** в 2,8 раза меньше JSON, читается быстрее и **сохраняет типы** (category, datetime, float32). Подробнее о форматах — модуль 3.

## 5. Сверка: свой groupby против pandas

```
group mean: NumPy 0.072 с, pandas 0.033 с, совпадают: True
group median совпадает с pandas: True
```

Наш NumPy-вариант медленнее pandas: `np.unique` сортирует ключи за $O(n\log n)$, а pandas факторизует через хэш-таблицу за $O(n)$. Это хороший урок. Векторизованный NumPy-код быстрее Python-циклов, но специализированная библиотека с правильным алгоритмом ещё быстрее. Понимать механику полезно, а в продакшен-коде используй `groupby`.

## 6. Типичные ошибки и как их отлаживать

| Ошибка | Симптом в pandas 3 | Как правильно |
|---|---|---|
| Цепочечное присваивание `df["a"][mask] = v` | `ChainedAssignmentError`, df не изменился | `df.loc[mask, "a"] = v` |
| Изменение подвыборки в надежде изменить df | `sub = df[mask]; sub["a"] = 0` — df не меняется (CoW) | Писать в `df.loc[...]` |
| `iterrows` / `apply(axis=1)` для простой арифметики | Медленно в 100–1000 раз | Векторные операции над колонками |
| merge без `validate` | Дубли ключей молча размножают строки | `validate="one_to_one"` / `"many_to_one"`, проверка `len` до и после |
| Сравнение с `NaN` через `==` | Всегда `False` | `isna()`, `notna()` |
| Строковые id картинок в одной таблице и int в другой | merge находит 0 совпадений | Привести типы ключей до merge |
| `inplace=True` | Не экономит память и ломает chaining; часть методов отказывается от него | Присваивать результат: `df = df.drop(...)` |
| Код из книги McKinney 3e (pandas 2.0) | Часть примеров с присваиванием ведёт себя иначе | Сверяться с [What's new in 3.0](https://pandas.pydata.org/docs/whatsnew/v3.0.0.html) |

## Ответы на вопросы для самопроверки

1. Любой объект, полученный из DataFrame (подвыборка, колонка), ведёт себя как копия: изменения в нём никогда не влияют на исходник. Физическое копирование откладывается до первой записи. Цепочечное присваивание `df["a"][mask] = v` больше никогда не меняет `df` и выдаёт `ChainedAssignmentError`.
2. `df.loc[mask, "col"] = value` — одной операцией над самим DataFrame.
3. Ключи факторизуются в номера групп (хэш-таблица, $O(n)$). Сумма и среднее накапливаются одним проходом по номерам (как `bincount`). Медиане нужен порядок внутри группы — сортировка $O(n\log n)$ или алгоритм выбора.
4. Проверяет кратность связи ключей. Если в справочнике категорий есть дубль id, `many_to_one`-merge без проверки размножит аннотации, и счётчики и метрики завысятся без единой ошибки.
5. `images.merge(anns[["image_id"]].drop_duplicates(), how="left", indicator=True)` и фильтр `_merge == "left_only"`. Или `~images.id.isin(anns.image_id)`.
6. Когда уникальных значений мало относительно числа строк (классы, камеры, разметчики, сплиты). Это экономит память, ускоряет groupby и сравнения, позволяет задать порядок значений.
7. Колоночный бинарный формат со сжатием: файл меньше, чтение быстрее (можно читать только нужные колонки), **типы сохраняются**. CSV теряет типы и плох для вложенных и строковых данных, JSON большой и медленно парсится.
