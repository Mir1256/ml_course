## 1. Зачем это нужно

Весь PyTorch — это ООП «по-питоновски»:
- `torch.utils.data.Dataset` — любой объект с `__len__` и `__getitem__`;
- `nn.Module` — класс с `forward`, а вызов `model(x)` идёт через `__call__`, который добавляет хуки и вызывает `forward`;
- трансформации `torchvision.transforms.Compose` — цепочка вызываемых объектов;
- конфиги экспериментов — dataclass или pydantic.

Если ты понимаешь протоколы Python, то видишь, почему `DataLoader` работает с твоим классом без наследования, и где именно сломается сборка батча (раздел 5).

## 2. Интуиция: «утиная» типизация и протоколы

В C# тип определяется **объявлением**: класс реализует `IEnumerable`, потому что так написано. В Python — **поведением** («если ходит как утка и крякает как утка…»). `for` работает с любым объектом, у которого есть `__iter__` (или `__getitem__`, бросающий `IndexError` в конце). `len()` — с любым, у которого есть `__len__`.

Такие наборы методов называются **протоколами**. Dunder-методы (double underscore: `__len__`, `__getitem__`, `__call__`, `__repr__`, `__eq__`, `__hash__`, `__enter__`/`__exit__`) — это способ встроить свой класс в синтаксис языка.

Для статической проверки (Pylance, mypy) протокол можно описать явно через `typing.Protocol`. Тогда проверяльщик поймёт, что `HFlip` — это `Transform`, хотя `HFlip` ни от чего не наследуется. `abc.ABC` — ближе к абстрактному классу C#: требует наследования и запрещает создавать экземпляр без реализации абстрактных методов.

| C# | Python |
|---|---|
| `interface IFoo` + явная реализация | `typing.Protocol` (структурно) или `abc.ABC` (номинально) |
| `record` / `readonly struct` | `@dataclass(frozen=True, slots=True)` |
| Свойство `{ get; }` | `@property` |
| `static` фабричный метод | `@classmethod` (получает класс, работает с наследниками) |
| Индексатор `this[int i]` | `__getitem__` |
| `IDisposable` + `using` | `__enter__`/`__exit__` + `with` |
| Перегрузка операторов | `__add__`, `__eq__`, `__lt__`, `__matmul__` (`@`) |
| `private` | Соглашение: `_name` — «внутреннее», `__name` — искажение имени (name mangling), но не защита |

## 3. Как это устроено: `__eq__`, `__hash__` и неизменяемость

Объект можно класть в `set` и использовать как ключ `dict`, только если он **хэшируем** и хэш согласован с равенством: `a == b ⇒ hash(a) == hash(b)`. Обычный `@dataclass` генерирует `__eq__` по полям, но ставит `__hash__ = None`: изменяемый объект с хэшем по полям сломал бы хэш-таблицу после изменения поля. `frozen=True` делает поля неизменяемыми и генерирует `__hash__`. Поэтому `Box(frozen=True)` можно класть в `set`, чтобы искать дубликаты разметки (урок 11).

`slots=True` убирает у каждого экземпляра `__dict__`. Атрибуты хранятся компактно: меньше памяти и быстрее доступ. Для миллионов рамок это заметно.

## 4. Пробелы — в коде

Файл: [код/dataset.py](код/dataset.py):

```python
@dataclass(frozen=True, slots=True)
class Box:
    x1: float
    y1: float
    x2: float
    y2: float
    label: str = "obj"

    def __post_init__(self):                       # валидация сразу при создании
        if self.x2 <= self.x1 or self.y2 <= self.y1:
            raise ValueError(f"вырожденная рамка: {self}")

    @property
    def area(self) -> float:
        return (self.x2 - self.x1) * (self.y2 - self.y1)

    @classmethod
    def from_yolo(cls, cx, cy, w, h, img_w, img_h, label="obj") -> Box:
        return cls((cx - w / 2) * img_w, (cy - h / 2) * img_h, (cx + w / 2) * img_w, (cy + h / 2) * img_h, label)


@dataclass
class Sample:
    image: np.ndarray
    boxes: list[Box] = field(default_factory=list) # НЕ boxes: list = [] — урок 19


@runtime_checkable
class Transform(Protocol):
    def __call__(self, sample: Sample) -> Sample: ...


class HFlip:                                       # не наследует Transform, но является им по протоколу
    def __call__(self, sample: Sample) -> Sample:
        w = sample.image.shape[1]
        boxes = [replace(b, x1=w - b.x2, x2=w - b.x1) for b in sample.boxes]
        return Sample(sample.image[:, ::-1].copy(), boxes)


class BaseDataset(ABC):
    @abstractmethod
    def __len__(self) -> int: ...
    @abstractmethod
    def __getitem__(self, idx: int) -> Sample: ...
    def __iter__(self):
        for i in range(len(self)):
            yield self[i]
```

Вывод:

```
Box(x1=240.0, y1=120.0, x2=400.0, y2=360.0, label='person') | площадь: 38400.0 | хэшируема: True
валидация: вырожденная рамка: Box(x1=10, y1=10, x2=5, y2=20, label='obj')
len: 5 | рамок на картинках: [1, 2, 3, 1, 2]
HFlip — это Transform (по протоколу): True
первая рамка после отражения: Box(x1=66.0, y1=10.0, x2=96.0, y2=50.0, label='car')
абстрактный класс: Can't instantiate abstract class BaseDataset with abstract methods __getitem__, __len__
```

Детали:
- `dataclasses.replace` — способ «изменить» frozen-объект: создаёт копию с новыми значениями полей.
- В `HFlip` после `[:, ::-1]` стоит `.copy()`. Срез с отрицательным шагом — **view** с отрицательными strides (урок 21), а `torch.from_numpy` такие массивы не принимает.
- Отражение рамки: новые `x1 = W - x2`, `x2 = W - x1` (а не `W - x1`, `W - x2`, иначе `x1 > x2`). Тест «отразить дважды = тождество» ловит эту ошибку.

## 5. Сверка с PyTorch: `Dataset`, `DataLoader` и collate

Файл: [код/torch_dataloader.py](код/torch_dataloader.py):

```python
class TorchDetection(Dataset):
    def __init__(self, base): self.base = base
    def __len__(self): return len(self.base)
    def __getitem__(self, idx):
        s = self.base[idx]
        image = torch.from_numpy(s.image).permute(2, 0, 1).float() / 255
        boxes = torch.tensor([[b.x1, b.y1, b.x2, b.y2] for b in s.boxes], dtype=torch.float32)
        return image, boxes

def detection_collate(batch):
    images, boxes = zip(*batch)
    return torch.stack(images), list(boxes)
```

```
батч картинок: (4, 3, 64, 96) | рамок на картинках: [1, 2, 3, 1]
без своего collate_fn: stack expects each tensor to be equal size, but got [1, 4] at entry 0 and [2, 4] at entry
```

Стандартный `collate` складывает элементы батча через `torch.stack`. У картинок одинаковая форма, а у рамок — разное число строк, и `stack` падает. Это **классическая** ошибка при первом обучении детектора на своих данных. Решение — свой `collate_fn`: рамки возвращаются списком. Torchvision-детекторы и Ultralytics устроены так же: внутри Ultralytics рамки всего батча склеены в одну таблицу с колонкой «индекс картинки».

## 6. Типичные ошибки и как их отлаживать

| Ошибка | Симптом | Как правильно |
|---|---|---|
| `aug: list = []` в dataclass | `ValueError: mutable default` при определении класса | `field(default_factory=list)` |
| Изменяемый dataclass в `set` / как ключ | `TypeError: unhashable type` | `frozen=True` |
| `__getitem__` без `IndexError` на выходе за границы | `for` по датасету бесконечен | Явная проверка индекса |
| `model.forward(x)` вместо `model(x)` | Не работают хуки и некоторые обёртки | Всегда `model(x)` — вызов через `__call__` |
| Забыли `super().__init__()` в `nn.Module` | `AttributeError: cannot assign module before Module.__init__() call` | Первой строкой `__init__` |
| Нет `__repr__` | Логи и отладка показывают `<__main__.X object at 0x...>` | dataclass генерирует `__repr__` сам; иначе — написать |
| Глубокие иерархии наследования «как в C#» | Хрупкий код | Композиция + протоколы; наследование — для каркаса (`nn.Module`, `Dataset`) |

## Ответы на быструю проверку

1. `staticmethod` не получает ни экземпляра, ни класса — просто функция в пространстве имён класса. `classmethod` получает класс `cls`: альтернативные конструкторы (`Box.from_yolo`), которые у наследника создадут наследника.
2. `<module.ClassName object at 0x...>`. В отладчике, списках и интерактивной консоли вызывается `__repr__`; `print` использует `__str__`, а при его отсутствии — `__repr__`.
3. `__len__` и `__iter__` (или `__getitem__`, бросающий `IndexError` в конце — тогда `for` работает через него).
4. `typing.Protocol` с методом `__call__`: любой объект с таким методом совместим структурно. `@runtime_checkable` добавляет поддержку `isinstance`.
5. Dataclass запрещает изменяемые значения по умолчанию (общий объект для всех экземпляров, урок 19). Правильно — `field(default_factory=list)`.
6. Вызывает инициализацию базового класса. Python не вызывает конструктор родителя автоматически, если ты переопределил `__init__`.

## Ответы на вопросы для самопроверки

1. Протокол — набор методов, по которому определяется совместимость. `Protocol` — структурная типизация: класс подходит, если у него есть нужные методы, наследование не нужно. `ABC` — номинальная: нужен явный наследник; ABC запрещает создавать экземпляр без реализации абстрактных методов.
2. `__len__` и `__getitem__` (плюс `IndexError` на границе). `DataLoader` с map-style датасетом использует именно их.
3. Генерируемый `__eq__` сравнивает по полям. Если бы хэш тоже считался по полям, изменение поля после помещения в `set` сломало бы хэш-таблицу. Поэтому изменяемым dataclass хэш отключают. `frozen=True` запрещает изменения, и хэш по полям становится безопасным.
4. Именованные альтернативные способы создания (из YOLO, из COCO, из файла), которые корректно работают с наследниками через `cls`.
5. `nn.Module.__call__` вызывает `forward` и вокруг него — forward/backward-хуки и логику некоторых обёрток. Прямой вызов `forward` всё это обходит.
6. Стандартный collate склеивает поля батча `torch.stack`, а рамок на картинках разное количество — тензоры разной длины не стыкуются.
