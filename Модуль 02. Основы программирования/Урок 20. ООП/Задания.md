# Задания к уроку 20. ООП

Урок: [Урок 20. ООП.md](Урок%2020.%20ООП.md) · код урока: [код/](код/)

Решения клади в папку [решения/](решения/) рядом с этим файлом и пиши «проверь урок 20».

**🟢 Базовое — «Набор рамок как полноценный тип»** (`boxes.py` + `test_boxes.py`)
Класс `Boxes` — контейнер рамок одной картинки поверх NumPy-массива `(N, 4)` (формат xyxy):
1. `__len__`, `__getitem__` (индекс → `Box`, срез и булева маска → новый `Boxes`), `__iter__`, `__repr__` (`Boxes(n=3, format='xyxy')`).
2. `__eq__` с допуском `np.allclose`; объясни в docstring, почему тогда `__hash__ = None`.
3. Свойства `area` и `centers` (векторизованно), методы `clip(img_w, img_h)` и `filter(min_area)`.
4. Альтернативные конструкторы `Boxes.from_yolo(...)` и `Boxes.from_coco(...)` (COCO хранит `x, y, w, h`).
5. Тесты на каждый метод, включая пустой `Boxes`.

**🟡 Среднее — «Аугментации с общим интерфейсом»** (`augment.py` + `test_augment.py` + картинка)
1. Протокол `Transform` из урока. Реализуй `RandomHFlip(p)`, `RandomScale(min, max)`, `RandomCrop(h, w)` (рамки обрезаются, а рамки, у которых осталось меньше 30% площади, удаляются), `ColorJitter(brightness)`.
2. Случайность — через `np.random.Generator`, переданный в конструктор (воспроизводимость, урок 2).
3. `Compose` с `__repr__`, `__len__` и `__getitem__` (доступ к отдельной трансформации).
4. Тесты: при `p=0` трансформация — тождество; рамки после любой цепочки лежат внутри кадра; одинаковый сид даёт одинаковый результат.
5. Нарисуй исходную картинку `load_sample_image("china.jpg")` с 2 рамками и 6 случайных аугментаций с пересчитанными рамками.

**🔴 Со звёздочкой — «Мини-реестр и конфиги экспериментов»** (`registry.py` + `test_registry.py`)
1. Декоратор-реестр `@register("hflip")`, который кладёт класс трансформации в словарь `TRANSFORMS`. Функция `build(cfg: dict)` создаёт объект по конфигу `{"name": "hflip", "p": 0.5}`. Так устроены MMDetection и Ultralytics.
2. `@dataclass(frozen=True)` `ExperimentConfig` с вложенными dataclass (`data`, `model`, `train`), загрузкой из YAML или JSON и валидацией в `__post_init__` (lr > 0, batch ≥ 1, известные имена трансформаций).
3. Метод `override(**changes)` для вложенных полей по пути `"train.lr"` → новый конфиг (через `dataclasses.replace`).
4. Тесты: неизвестное имя → понятная ошибка; конфиг неизменяем; `override` не меняет исходный объект.
