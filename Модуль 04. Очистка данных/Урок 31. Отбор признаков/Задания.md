**🟢 Базовое — «Отбор внутри Pipeline»** (`pipeline_selection.py`)
На `load_breast_cancer` (30 признаков):
1. Сравни на 5×5 `RepeatedStratifiedKFold`: (а) все признаки; (б) `SelectKBest(mutual_info_classif, k)` для k = 3, 5, 10, 20; (в) `SelectFromModel(LogisticRegression(l1_ratio=1, solver="liblinear", C))`. Всё — внутри `Pipeline` со `StandardScaler`.
2. Посчитай корреляционную матрицу признаков и найди группы почти-дублей (|ρ| > 0,95). Объясни, почему отбор выбирает из группы «случайного» представителя.
3. Вывод: сколько признаков реально нужно и какой ценой в качестве.

**🟡 Среднее — «Стабильность отбора»** (`stability.py` + график)
1. Запусти L1-логрег и `SelectKBest` на 200 бутстрап-выборках (урок 18) `load_breast_cancer`. Для каждого признака посчитай долю выборок, где он отобран.
2. Нарисуй «карту стабильности» (признаки × метод, цвет — частота отбора). Какие признаки отбираются всегда, а какие — «как повезёт»?
3. Посчитай индекс Жаккара между наборами признаков из разных бутстрап-выборок (урок 11) — среднюю стабильность каждого метода.
4. Свяжи с уроком 27: почему нестабильный отбор — признак того, что выводы о «важных признаках» ненадёжны?

**🔴 Со звёздочкой — «Важности по срезам и группам»** (`grouped_importance.py` + `test_grouped_importance.py`)
1. Обобщи `permutation_importance_np`: параметр `groups: dict[str, list[int]]` — перестановка **группы** столбцов вместе (одной и той же перестановкой строк). Тест: для двух признаков-копий групповая важность ≥ суммы индивидуальных.
2. Параметр `slice_mask`: важность, посчитанная только на подмножестве объектов (например, «ночь»).
3. Сгенерируй данные, где признак `exposure` важен только ночью, а `blur` — только днём. Покажи, что общая важность их недооценивает, а важности по срезам находят.
4. Добавь доверительные интервалы важностей через повторы перестановок и бутстрап тестовой выборки (урок 18).
