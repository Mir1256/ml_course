## 1. Зачем это нужно

Признаков бывает больше, чем нужно: сотни метаданных съёмки, тысячи HOG-компонент, десятки сгенерированных признаков из урока 28. Лишние признаки:
- добавляют шум и переобучение;
- замедляют обучение и инференс;
- мешают понять, **от чего** зависит качество модели. «Почему детектор хуже ночью?» — ответ ищут через важность признаков.

Отбор признаков — ещё и место для тонкой утечки (урок 27): отбери признаки на всём датасете — и модель на чистом шуме покажет 73% accuracy.

## 2. Интуиция: три семьи методов

- **Filter** — оценить каждый признак **отдельно**, без модели: корреляция или F-статистика с целью, взаимная информация, дисперсия. Быстро, но не видит взаимодействий и избыточности: два одинаково полезных признака-дубля получат одинаково высокие оценки.
- **Wrapper** — перебирать **наборы** признаков, обучая модель и оценивая её на кросс-валидации: прямой отбор (добавлять лучший), обратный (убирать худший), RFE. Учитывает взаимодействия и избыточность, но дорого и само переобучается на CV, если выбирать долго.
- **Embedded** — отбор как часть обучения: L1-регуляризация зануляет веса (урок 13), деревья дают важности. Компромисс по цене и качеству.

Отдельно — **важность признака**, то есть насколько модель на него опирается. Самый честный общий способ — **permutation importance**: перемешать столбец на тестовой выборке и посмотреть, насколько упало качество.

## 3. Математика

### 3.1. Взаимная информация

$$I(X; Y) = H(X) + H(Y) - H(X, Y) = \text{KL}\big(p(x, y)\,\|\,p(x)p(y)\big) \ge 0$$

(энтропия и KL — урок 15). $I = 0$ ⇔ $X$ и $Y$ независимы. В отличие от корреляции, взаимная информация ловит **любую** связь, а не только линейную. Тест `test_mi_nonlinear_dependence`: $y = [x^2 > 4]$ при корреляции ≈ 0 даёт $I = H(Y)$ — полная зависимость. Для непрерывных признаков $I$ оценивают по гистограммам (как в нашем коде, по квартилям) или kNN-оценщиком (Kraskov et al.). Его использует `mutual_info_classif`.

### 3.2. ANOVA F-статистика

Для числового признака и классов $k = 1..K$:

$$F = \frac{\text{дисперсия между классами}/(K - 1)}{\text{дисперсия внутри классов}/(n - K)}.$$

Большое $F$ значит, что средние признака заметно различаются по классам относительно разброса внутри класса. Это фильтр «линейной» разделимости по одному признаку.

### 3.3. Почему полный перебор невозможен, а жадный переобучается

Всех подмножеств $d$ признаков — $2^d$ (урок 11). Жадный прямой отбор обучает $\sum_{s=0}^{k-1}(d - s) = O(kd)$ моделей. Но каждое решение «добавить признак $j$» — выбор максимума из многих **шумных** CV-оценок. После того как реальные признаки исчерпаны, жадный алгоритм добавляет шумовой признак, случайно поднявший CV-оценку на долю процента. В коде урока он выбрал 2 настоящих признака и 3 шумовых. Это множественные сравнения из урока 18. Отсюда правило: качество отбора проверяют на **отдельных** данных (вложенная кросс-валидация).

### 3.4. Permutation importance и смещение impurity importance

Пусть $s$ — качество модели на тесте, $s_j$ — качество после случайной перестановки столбца $j$. Тогда

$$\text{PI}_j = s - \mathbb{E}[s_j].$$

Перестановка сохраняет распределение признака, но рвёт его связь с целью и с другими признаками. У бесполезного признака $\text{PI} \approx 0$ (может быть чуть отрицательным из-за шума).

**Impurity importance** деревьев (MDI, `feature_importances_`) — суммарное уменьшение неоднородности узлов на разбиениях по признаку, посчитанное **на обучающей выборке**. У признака с тысячами уникальных значений больше возможных порогов, и дерево находит среди них случайно «удачные» разбиения обучающих данных. Поэтому MDI завышает важность высококардинальных признаков, даже если это чистый шум (id кадра). Permutation importance на тесте этим не страдает.

**Ловушка коррелированных признаков:** если два признака почти копии, перестановка одного почти не вредит — модель берёт информацию из второго. Обе важности окажутся низкими, хотя информация важна. Решение — переставлять группы коррелированных признаков вместе.

## 4. Реализация с нуля

Файл: [код/selection.py](код/selection.py):

```python
def mutual_information_discrete(x, y):
    """I(X;Y) = H(X) + H(Y) - H(X,Y)"""
    joint = np.unique(np.c_[x, y], axis=0, return_inverse=True)[1].ravel()
    return entropy_discrete(x) + entropy_discrete(y) - entropy_discrete(joint)

def forward_selection(model, X, y, k, cv=5):
    chosen, rest = [], list(range(X.shape[1]))
    for _ in range(k):
        scores = [cross_val_score(model, X[:, chosen + [j]], y, cv=cv).mean() for j in rest]
        best = rest[int(np.argmax(scores))]
        chosen.append(best); rest.remove(best)
    return chosen

def permutation_importance_np(model, X, y, n_repeats=10, seed=0):
    rng = np.random.default_rng(seed)
    base = model.score(X, y)
    drops = np.zeros((n_repeats, X.shape[1]))
    for r in range(n_repeats):
        for j in range(X.shape[1]):
            Xp = X.copy()
            Xp[:, j] = rng.permutation(Xp[:, j])
            drops[r, j] = base - model.score(Xp, y)
    return drops.mean(axis=0)
```

Разбор:
- **Filter** находит информативные признаки, но вперемешку с избыточными (5, 6): он не видит, что они дублируют уже выбранные. `VarianceThreshold` вообще не смотрит на цель — он лишь отсекает почти-константы.
- **Прямой отбор** (свой совпал с `SequentialFeatureSelector` до признака) взял 1 и 4, после чего добавил три шумовых. Это 3.3 вживую: линейной модели хватило двух признаков, а дальше жадный выбор «ловил» шум CV-оценок.
- **RFE** и **L1** нашли 4 из 5 информативных. L1 оставила ещё несколько шумовых с маленькими весами — сила регуляризации `C` подбирается по CV.
- **Impurity importance** у случайного id в 9 раз выше, чем у бинарного шума. Permutation importance честно ставит обоим ≈ 0. Наша реализация вывела в топ-10 ровно признаки 0–9 — все информативные и их комбинации.
- **Отбор до CV** на чистом шуме — 73%, внутри `Pipeline` — 55%, то есть близко к угадыванию (небольшое превышение 50% — шум оценки на 400 объектах).

## 6. Типичные ошибки и как их отлаживать

| Ошибка | Последствие | Как правильно |
|---|---|---|
| Отбор признаков на всём датасете до CV | Утечка, оптимистичная оценка (73% на шуме) | Отбор внутри `Pipeline`; для оценки самого отбора — вложенная CV |
| Долгий жадный отбор по одной CV | Переобучение на шум CV | Ограничить число шагов; проверить на отложенных данных |
| `feature_importances_` деревьев как истина | Высококардинальные шумовые признаки (id, время) кажутся важными | Permutation importance на тестовой выборке |
| Вывод «признак не важен» при коррелированных признаках | Важность «размазывается» между копиями | Группировать коррелированные признаки, переставлять группой |
| Фильтр по корреляции для нелинейных связей | Пропуск важных признаков | Взаимная информация; модельные методы |
| Отбор по p-значениям без поправки | Множественные сравнения (урок 18) | Поправка или модельные методы |
| Удаление признака с низкой важностью «потому что модель его не использует» | В другом срезе данных (ночью) он может быть критичен | Смотреть важности по срезам |

## Ответы на вопросы для самопроверки

1. Filter — оценка признаков по отдельности без модели: быстро, но не видит взаимодействий и избыточности. Wrapper — перебор наборов с обучением модели: учитывает взаимодействия, но дорого и переобучается на CV. Embedded — отбор внутри обучения (L1, деревья): дёшево и учитывает модель, но зависит от её предположений.
2. $I(X;Y) = H(X) + H(Y) - H(X,Y)$. Равна нулю только при независимости и ловит любую, в том числе нелинейную, связь. Корреляция — только линейную.
3. Каждый шаг выбирает максимум из многих шумных CV-оценок. Когда полезные признаки кончились, побеждает шумовой признак, случайно поднявший оценку, — это множественные сравнения.
4. Перемешиваем значения признака на тестовой выборке, рвём его связь с целью, и падение качества — важность. На тесте — чтобы мерить вклад в обобщение, а не в запоминание обучающих данных.
5. MDI считается на обучающей выборке. У признака с многими значениями больше возможных порогов, и среди них находятся случайно «удачные» разбиения, уменьшающие неоднородность. Это переобучение, а не полезность.
6. Модель может взять информацию из любой копии. Перестановка одной копии мало вредит, и важность «размазывается»: обе копии выглядят малозначимыми.
7. Поставить отбор шагом `Pipeline` перед моделью и передать весь пайплайн в `cross_val_score`: отбор будет обучаться заново на train-части каждого фолда. Для оценки самой процедуры отбора и подбора гиперпараметров — вложенная CV.
