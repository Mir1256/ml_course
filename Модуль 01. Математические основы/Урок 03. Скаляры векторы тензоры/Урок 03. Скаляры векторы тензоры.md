## 1. Зачем это нужно

Когда YOLO получает кадр, он видит не «картинку», а тензор формы `(1, 3, 640, 640)`. На выходе — тензоры предсказаний, а между ними — сотни операций над тензорами. Самая частая ошибка в DL-коде — **несовпадение форм (shape mismatch)**. Вторая по частоте — ещё хуже: формы совпали благодаря broadcasting, но смысл осей перепутан. Модель тогда учится, но на мусоре.

Векторы нужны и вне нейросетей: признаки объекта — вектор, эмбеддинг лица из модели re-identification — вектор. Поиск «похожих картинок» — это поиск ближайших векторов по косинусу.

## 2. Интуиция

- **Скаляр** — одно число: learning rate, значение функции потерь, IoU.
- **Вектор** — упорядоченный набор чисел. Два взгляда, и оба нужны: *стрелка* в пространстве (направление + длина) и *точка* (объект с $d$ признаками).
- **Матрица** — таблица; следующий урок.
- **Тензор** в ML — многомерный массив. Порядок (число осей) у скаляра 0, у вектора 1, у матрицы 2, у RGB-картинки 3, у батча картинок 4, у батча видеоклипов 5. В физике у слова «тензор» более строгий смысл (полилинейное отображение), в DL так называют просто `ndarray`.

**Скалярное произведение** отвечает на вопрос «насколько два вектора смотрят в одну сторону». **Норма** — «насколько вектор длинный». **Косинус** — скалярное произведение, очищенное от длин: только направление. Поэтому косинус хорош для эмбеддингов: «яркость» эмбеддинга (его длина) часто зависит от качества кадра, а «смысл» живёт в направлении.

## 2б. Освежение базы

**Операции над векторами** $u, v \in \mathbb{R}^d$: сложение покомпонентно, умножение на скаляр $\alpha u = (\alpha u_1, \dots, \alpha u_d)$.

**Скалярное произведение (dot product):** $u \cdot v = u^\top v = \sum_{i=1}^d u_i v_i$.

**Нормы (norms):**
- $\|v\|_2 = \sqrt{\sum v_i^2} = \sqrt{v^\top v}$ — евклидова длина;
- $\|v\|_1 = \sum |v_i|$ — «манхэттенская», даёт L1-регуляризацию (Lasso, урок 39);
- $\|v\|_\infty = \max_i |v_i|$ — нужна в adversarial-атаках (возмущение «не больше ε на пиксель»).

Аксиомы нормы: $\|v\| \ge 0$ и $\|v\| = 0 \iff v = 0$; $\|\alpha v\| = |\alpha|\,\|v\|$; неравенство треугольника $\|u+v\| \le \|u\| + \|v\|$.

**Линейная комбинация** $\alpha_1 v_1 + \dots + \alpha_k v_k$. **Линейная оболочка (span)** — все такие комбинации. Векторы **линейно независимы**, если $\sum \alpha_i v_i = 0$ только при всех $\alpha_i = 0$, то есть ни один не выражается через остальные. **Базис** — независимый набор, оболочка которого — всё пространство. Его размер — **размерность**.

**Тензоры и формы.** `shape` — кортеж длин по осям. Число элементов — произведение длин. Порядок осей — соглашение:
- **NCHW** (batch, channels, height, width) — PyTorch, YOLO;
- **NHWC** — TensorFlow по умолчанию, OpenCV/PIL для одной картинки (HWC).

## 3. Математика

### 3.1. Неравенство Коши–Буняковского и косинус

Утверждение: $|u \cdot v| \le \|u\|_2 \|v\|_2$.

**Вывод.** Пусть $v \neq 0$. Рассмотрим функцию $f(t) = \|u - t v\|_2^2 \ge 0$ для любого $t \in \mathbb{R}$:

$$f(t) = (u - tv)^\top (u - tv) = u^\top u - 2t\,u^\top v + t^2 v^\top v.$$

Это квадратный трёхчлен по $t$, который нигде не отрицателен. Значит, его дискриминант $\le 0$:

$$4(u^\top v)^2 - 4(u^\top u)(v^\top v) \le 0 \;\Rightarrow\; (u^\top v)^2 \le \|u\|^2\|v\|^2. \;\blacksquare$$

Следствие: $\cos\theta = \dfrac{u \cdot v}{\|u\|\,\|v\|} \in [-1, 1]$ — определение угла корректно в любой размерности, хоть в 512-мерном пространстве эмбеддингов.

### 3.2. Проекция как задача оптимизации

Ищем точку на прямой $\{t u\}$, ближайшую к $v$: минимизируем $g(t) = \|v - t u\|^2 = v^\top v - 2t\,u^\top v + t^2 u^\top u$.

Производная: $g'(t) = -2u^\top v + 2t\,u^\top u = 0 \Rightarrow t^* = \dfrac{u^\top v}{u^\top u}$.

$$\operatorname{proj}_u v = \frac{u^\top v}{u^\top u}\, u.$$

Проверка ортогональности остатка: $u^\top(v - t^* u) = u^\top v - \frac{u^\top v}{u^\top u} u^\top u = 0$.

Это первый пример того, что пройдёт через весь курс: **«найти лучшее приближение» = «минимизировать квадрат нормы ошибки» = «остаток ортогонален»**. Метод наименьших квадратов (урок 36) — та же проекция, только на подпространство. PCA (урок 48) — проекция на лучшее подпространство.

### 3.3. Евклидово расстояние и косинус для нормированных векторов

Если $\|a\| = \|b\| = 1$, то

$$\|a - b\|^2 = a^\top a - 2a^\top b + b^\top b = 2 - 2\cos\theta.$$

То есть после L2-нормировки сортировка по расстоянию и по косинусу **совпадают**. Поэтому в re-ID и CLIP эмбеддинги нормируют, и дальше можно пользоваться любой из двух метрик.

### 3.4. Сколько памяти занимает тензор

Число элементов = $\prod_i \text{shape}_i$, байты = элементы × размер типа (float32 — 4 байта, float16 — 2, uint8 — 1). Батч `(16, 3, 640, 640)` float32 — это ≈ 19,7 млн чисел ≈ 79 МБ. И это только вход: активации внутри сети на порядок больше. На твоих 4 ГБ это прямо ограничивает размер батча.

## 4. Реализация с нуля на NumPy

Файл: [код/vectors.py](код/vectors.py). Ключевые функции:

```python
def cosine(u: np.ndarray, v: np.ndarray, eps: float = 1e-12) -> float:
    """cos угла между векторами; eps защищает от деления на ноль у нулевого вектора."""
    return float(u @ v / max(np.linalg.norm(u) * np.linalg.norm(v), eps))


def project(v: np.ndarray, u: np.ndarray) -> np.ndarray:
    """Ортогональная проекция v на прямую, натянутую на u: (u·v / u·u) u."""
    return (u @ v) / (u @ u) * u


def pairwise_cosine(A: np.ndarray, B: np.ndarray, eps: float = 1e-12) -> np.ndarray:
    """Матрица косинусов (n, m) между строками A (n, d) и B (m, d) — одно матричное умножение."""
    A_n = A / np.maximum(np.linalg.norm(A, axis=1, keepdims=True), eps)   # keepdims -> (n, 1), иначе broadcasting сломается
    B_n = B / np.maximum(np.linalg.norm(B, axis=1, keepdims=True), eps)
    return A_n @ B_n.T


def hwc_uint8_to_chw_float(img: np.ndarray) -> np.ndarray:
    """(H, W, 3) uint8 [0..255] -> (3, H, W) float32 [0..1] — как делает torchvision ToTensor."""
    assert img.dtype == np.uint8 and img.ndim == 3 and img.shape[2] == 3
    return img.transpose(2, 0, 1).astype(np.float32) / 255.0


def channel_mean_std(batch: np.ndarray) -> tuple[np.ndarray, np.ndarray]:
    """Поканальные mean/std по батчу NCHW: усредняем по осям N, H, W -> вектор длины C."""
    return batch.mean(axis=(0, 2, 3)), batch.std(axis=(0, 2, 3))
```

`pairwise_cosine` — главный приём урока. Вместо двойного цикла по парам: нормируем строки, и вся матрица косинусов получается **одним** матричным умножением. Так устроен поиск в CLIP по миллионам картинок.

Нормализация батча использует broadcasting: `mean[None, :, None, None]` превращает вектор формы `(3,)` в `(1, 3, 1, 1)`, и он «растягивается» на `(N, 3, H, W)`.

Вывод `python vectors.py`:

```
u·v = 2.0 | ||u||_2 = 3.0 | ||u||_1 = 5.0 | ||u||_inf = 2.0
cos(u, v) = 0.2722 | proj_u v = [0.22222222 0.44444444 0.44444444]
batch shape (N, C, H, W) = (8, 3, 64, 48) | dtype float32 | байт: 294912
mean по каналам: [0.497 0.501 0.5  ] | std: [0.29  0.291 0.291]
после нормализации mean ≈ [ 5.e-06  2.e-06 -6.e-06]
```

Остаток ~1e-6 после нормализации — это погрешность float32, а не ошибка. Ноль в float32 «точнее чем 1e-7» обычно не получить.

Что важно заметить:
- `scipy.spatial.distance.cosine` возвращает **расстояние** $1 - \cos$, а не сходство. Классическая ловушка.
- В PyTorch HWC → CHW делается через `permute(2, 0, 1)`, а не через `reshape`. `reshape(3, H, W)` тоже даст нужную форму, но перемешает пиксели. Это самый коварный баг с тензорами: ошибки нет, а данные испорчены.
- Тесты: [код/test_vectors.py](код/test_vectors.py) проверяют ортогональность остатка проекции, границы косинуса, неравенство треугольника и пайплайн HWC → NCHW.

## 6. Типичные ошибки и как их отлаживать

| Ошибка | Пример | Как ловить |
|---|---|---|
| `reshape` вместо `transpose`/`permute` | `img.reshape(3, H, W)` из HWC | Тест на маленькой картинке с известными значениями: пиксель `[0, 0]` должен остаться пикселем `[:, 0, 0]` |
| Broadcasting `(n,)` против `(n, 1)` | `A / np.linalg.norm(A, axis=1)` для матрицы `(n, n)` делит **столбцы**, а не строки, и ошибки нет | `keepdims=True`; `assert x.shape == (...)` после каждой нетривиальной операции |
| Переполнение uint8 | `img + 10` у пикселя 250 даёт 4 | Сначала `astype(np.float32)`, потом арифметика |
| Деление на ноль у нулевого вектора | Чёрный кадр → эмбеддинг из нулей → `nan` в косинусе | `eps` в знаменателе, как в `cosine` |
| Перепутаны NCHW и NHWC | Модель «учится», но плохо | Печатать `x.shape` на входе модели; в PyTorch `x.shape[1]` должен быть 3 (или число каналов) |
| Усреднение не по тем осям | `batch.mean(axis=0)` вместо `(0, 2, 3)` даёт `(C, H, W)`, а не `(C,)` | Сначала ответить себе, какая форма должна получиться |

## Ответы на диагностику

1. $u \cdot v = 3 + 0 + 8 = 11$; $\|u\|_2 = 5$, $\|u\|_1 = 7$, $\|u\|_\infty = 4$; $\|v\|_2 = 3$, $\cos = 11/15 \approx 0{,}733$.
2. $\operatorname{proj}_u v = \frac{11}{25}(3, 0, 4) = (1{,}32;\ 0;\ 1{,}76)$.
3. Зависимы: $(2,4,6) = 2\cdot(1,2,3)$. Оболочка — плоскость, размерность 2 (векторы $(1,2,3)$ и $(0,1,0)$ независимы).
4. $16 \cdot 3 \cdot 224 \cdot 224 = 2\,408\,448$ чисел × 4 байта ≈ 9,63 МБ (≈ 9,19 МиБ). `x[5, 2, 10, 20]` — шестая картинка батча, третий канал (B в RGB), строка 10, столбец 20.
5. 0,95 — эмбеддинги почти сонаправлены, скорее всего один человек. −0,1 — почти ортогональны, разные люди. Косинус не зависит от длины эмбеддинга, а длина часто отражает «уверенность» или качество кадра, а не личность. Для L2-нормированных векторов обе метрики дают одинаковый порядок.

## Ответы на вопросы для самопроверки

1. Матрица — тензор порядка 2; тензор в DL — массив с любым числом осей. Порядок 0: значение loss; 1: вектор логитов классов; 2: ч/б картинка H×W; 3: RGB-картинка C×H×W; 4: батч N×C×H×W; 5: батч видеоклипов N×C×T×H×W.
2. См. 3.2: минимизируем $\|v - tu\|^2$ по $t$, получаем $t^* = u^\top v / u^\top u$. Остаток ортогонален, потому что в минимуме производная $-2u^\top(v - t^*u) = 0$. Это и есть условие ортогональности.
3. Из неравенства Коши–Буняковского $|u^\top v| \le \|u\|\|v\|$; вывод — через неотрицательность квадратного трёхчлена $\|u - tv\|^2$.
4. Когда векторы L2-нормированы: $\|a-b\|^2 = 2 - 2\cos\theta$ — монотонно убывающая функция косинуса, поэтому порядок совпадает.
5. NCHW — каналы перед пространственными осями (PyTorch), NHWC — каналы последними (TensorFlow, OpenCV, PIL). `reshape` только переинтерпретирует тот же линейный порядок элементов в памяти, а переход между форматами требует **перестановки** осей (`transpose`/`permute`), меняющей порядок обхода.
6. L2 — евклидово расстояние, MSE, L2-регуляризация (weight decay), нормировка эмбеддингов. L1 — Lasso и разреженность, MAE, робастные потери. L∞ — adversarial-атаки (PGD с ограничением на пиксель), равномерная сходимость. Фробениусова (урок 4) — нормы матриц весов.
7. $32 \cdot 3 \cdot 640 \cdot 640 = 39\,321\,600$ чисел: float32 ≈ 157 МБ, float16 ≈ 79 МБ.
