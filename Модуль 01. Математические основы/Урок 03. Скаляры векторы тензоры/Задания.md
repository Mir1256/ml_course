# Задания к уроку 3. Скаляры, векторы, тензоры

Решения клади в папку [решения/](решения/) рядом с этим файлом и пиши «проверь урок 3». Правило для всех заданий модуля: никаких Python-циклов по элементам там, где возможна векторизация.

**🟢 Базовое — «Инструменты»** (`basics.py` + `test_basics.py`)
Реализуй:
- `l2_normalize(X, axis=-1, eps=1e-12)` — нормировка вдоль любой оси тензора любой формы;
- `are_independent(vectors: np.ndarray) -> bool` — линейная независимость строк (можно `np.linalg.matrix_rank`, но объясни в docstring, почему сравнение с нулём нужно делать с допуском);
- `tensor_megabytes(shape, dtype) -> float`.

Тесты: нормы строк после `l2_normalize` равны 1 для осей 0, 1 и −1 на тензоре `(4, 5, 6)`; нулевой вектор не даёт `nan`; ответы задач 3 и 4 диагностики.

**🟡 Среднее — «Поиск похожих картинок»** (`retrieval.py` + `retrieval.png`)
Данные: `sklearn.datasets.load_digits()` — 1797 изображений 8×8, каждое — вектор из 64 чисел.
1. Для каждого изображения найди ближайшего соседа (исключая само изображение) по косинусу и по евклидову расстоянию. Делай это **без цикла по парам**: одна матрица сходств `(1797, 1797)`.
2. Посчитай top-1 accuracy: доля случаев, когда метка соседа совпала с меткой запроса. Сравни две метрики.
3. Повтори после `l2_normalize` и покажи, что теперь косинус и евклид дают **одинаковых** соседей (это раздел 3.3 урока).
4. Нарисуй 5 запросов и их 5 ближайших соседей в сетке `matplotlib`.

Ответь в конце файла: почему на сырых пикселях метрики дают разное качество? (Подумай, что значит длина вектора для изображения цифры.)

**🔴 Со звёздочкой — «Быстрые попарные расстояния»** (`pairwise.py` + `test_pairwise.py`)
1. Выведи на бумаге $\|a - b\|^2 = \|a\|^2 + \|b\|^2 - 2a^\top b$ и реализуй через неё `pairwise_sq_dist(A, B)` для матриц `(n, d)` и `(m, d)` одним матричным умножением.
2. Сравни с `scipy.spatial.distance.cdist(..., "sqeuclidean")` на float32-данных `(2000, 512)` со средним 100 и разбросом 1. Найди максимальную абсолютную ошибку. Получи отрицательные «квадраты расстояний» и объясни, откуда они (катастрофическая потеря точности, catastrophic cancellation).
3. Почини: центрирование данных до вычисления, накопление в float64, `np.maximum(…, 0)`. Покажи, что каждое из исправлений даёт по ошибке.
4. Матрица `(100000, 100000)` float32 не влезет в память — посчитай, сколько ей нужно. Напиши генератор `topk_neighbors_chunked(A, B, k, chunk=4096)`, который находит $k$ ближайших соседей, обрабатывая `B` кусками, с памятью $O(\text{chunk} \cdot n)$. Тест: совпадает с полным вычислением на маленьких данных.
