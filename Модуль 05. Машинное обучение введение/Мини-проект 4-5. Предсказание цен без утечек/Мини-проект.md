# Мини-проект 4/5. Предсказание цен без утечек

**Модули 4–5** · ≈ 6,5 ч · неделя 15 · пререквизиты: уроки 27–35
**Данные:** Ames Housing — Kaggle «House Prices: Advanced Regression Techniques» ([kaggle.com/competitions/house-prices-advanced-regression-techniques](https://www.kaggle.com/competitions/house-prices-advanced-regression-techniques); 1460 домов, 79 признаков смешанных типов). Без аккаунта Kaggle: `fetch_openml(name="house_prices", as_frame=True)` — проверь, что версия содержит те же колонки.
**Решение:** папка [решения/](решения/) · сдача — «проверь мини-проект 4/5»

---

## Почему этот проект, а не CV

Здесь нет картинок, но есть всё, на чём ломаются реальные пайплайны:
- 79 признаков смешанных типов;
- пропуски, которые **что-то значат** (`PoolQC = NA` — «бассейна нет», а не «не знаем»);
- порядковые категории («плохо < средне < хорошо»), редкие категории, выбросы;
- скошенная цель.

Если ты соберёшь это в один честный пайплайн, такой же пайплайн для метаданных детекции (камеры, время, условия съёмки) будет делом часа.

## Техническое задание

### Часть 1. EDA и аудит (≈ 1 ч)

1. Типы колонок, доля пропусков, распределение цели `SalePrice` (и `log`), топ корреляций с целью (Пирсон и Спирмен, урок 16).
2. Найди в описании данных (`data_description.txt` на Kaggle) признаки, где NA означает «отсутствует», а не «неизвестно». Перечисли их — это MNAR с известным смыслом (урок 27).
3. Найди выбросы: дома с огромной площадью и низкой ценой (в Ames их несколько, авторы датасета советуют их обсудить). Реши, удалять ли их из **train**, и обоснуй. Тест так не чистят!

### Часть 2. Пайплайн (≈ 2 ч)

1. Отложи 20% как test **сразу** и не трогай до конца.
2. Цель — $\log(1 + \text{SalePrice})$; метрика — RMSE в логарифмах (то есть «относительная» ошибка, как на Kaggle).
3. Один `ColumnTransformer`:
   - NA «отсутствует» → категория `"None"` / ноль;
   - числовые → медиана + индикатор пропуска + `log1p` для скошенных (|skew| > 0,75, определяется **внутри** пайплайна) + масштабирование;
   - порядковые (`ExterQual`, `KitchenQual`, …) → `OrdinalEncoder` с явным порядком `Po < Fa < TA < Gd < Ex`;
   - номинальные → `OneHotEncoder(min_frequency=10, handle_unknown="infrequent_if_exist")`;
   - районы (`Neighborhood`) → дополнительно `TargetEncoder` (кросс-фиттинг, урок 28).
4. Инженерия признаков (свой трансформер, урок 34): общая площадь, возраст дома и ремонта на момент продажи, число ванных, наличие гаража / бассейна / второго этажа.
5. Требование: `cross_val_score(model, X_train_raw, y_train)` запускается на **сыром** DataFrame и не падает.

### Часть 3. Модели и подбор (≈ 2 ч)

1. Бейзлайн — медиана цели (`DummyRegressor(strategy="median")`).
2. Линейная регрессия без регуляризации (покажи, что с one-hot и коллинеарными признаками она нестабильна, урок 5).
3. Ridge с подбором `alpha` по логарифмической сетке (`RandomizedSearchCV` + `loguniform`, урок 35).
4. Та же Ridge **без** инженерии признаков — для сравнения.
5. Оцени выбранную модель **вложенной** CV и сравни с невложенной.
6. Финал: refit на всём train, одна оценка на test.

### Часть 4. Отчёт об утечках (≈ 1,5 ч)

Найди (или создай нарочно) и задокументируй минимум три утечки, сравни метрики «с утечкой / без»:
- импутация и масштабирование до сплита;
- отбор признаков или target encoding на всех данных;
- признаки, вычисленные из цели или из будущего (например, `SalePrice` по району **с** учётом самого дома; год продажи при случайном сплите против временного сплита по `YrSold`).

## Критерии готовности

- [ ] `cross_val_score` запускается на сыром DataFrame train и не падает; вся предобработка — внутри одного `Pipeline`.
- [ ] CV-RMSE(log) лучше бейзлайна-медианы **и** лучше модели без инженерии признаков; разница подтверждена (среднее ± std по фолдам или парным сравнением).
- [ ] Есть отчёт об утечках: какие найдены, как устранены, как менялись метрики.
- [ ] Вложенная и невложенная оценки приведены и объяснены; test использован один раз.
- [ ] Финальный пайплайн сохранён (`joblib`) и предсказывает на новых сырых строках (проверено на 5 строках test).
