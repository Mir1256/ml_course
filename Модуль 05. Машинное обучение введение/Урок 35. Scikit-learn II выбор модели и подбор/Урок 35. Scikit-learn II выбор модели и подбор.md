## 1. Зачем это нужно

У любой модели есть **гиперпараметры** — то, что не выучивается из данных градиентом, а задаётся заранее:
- `C` и `gamma` у SVM;
- глубина дерева;
- learning rate, размер батча, аугментации и `imgsz` у YOLO.

От них качество зависит не меньше, чем от выбора алгоритма. Подбирать их нужно так, чтобы:
1. найти хорошие значения за разумное число запусков (на твоей GTX 1050 Ti один запуск дообучения детектора — часы);
2. **не обмануть себя**: если выбирать лучший из 143 вариантов по той же оценке, которой потом хвалишься, оценка завышена.

## 2. Интуиция

- **Grid search** — перебрать все комбинации из сетки. Просто, но число запусков растёт как произведение размеров осей (урок 11). Кроме того, по каждой оси пробуется всего несколько значений.
- **Random search** — выбирать комбинации случайно из распределений. При том же бюджете он пробует **больше различных значений каждого параметра**. Обычно важны лишь 1–2 гиперпараметра из многих, и random search исследует именно их плотнее.
- **Successive halving / Hyperband** — запустить много кандидатов на малом бюджете (мало данных, мало эпох), отбросить худшую часть, оставшимся дать больше бюджета. Экономит время на заведомо плохих кандидатах.
- **Байесовская оптимизация** (Optuna, урок 67) — строить модель «гиперпараметры → качество» по уже проведённым запускам и выбирать следующий запуск там, где ожидается улучшение.
- **Вложенная кросс-валидация** — честная оценка **всей процедуры** «подбери гиперпараметры и обучи». Внешний цикл оценивает, внутренний выбирает.

## 3. Математика

### 3.1. Почему random search лучше grid

Пусть «хорошая» область занимает долю $q$ пространства гиперпараметров (например, лучшие 5%, $q = 0{,}05$). Каждая случайная точка попадает туда с вероятностью $q$ независимо. Вероятность, что за $n$ запусков хоть одна попадёт:

$$1 - (1 - q)^n,\qquad 1 - 0{,}95^{60} \approx 0{,}954.$$

60 случайных запусков почти наверняка дают точку из лучших 5% — **независимо от размерности** пространства. Сетка с тем же бюджетом в 2D — это $\approx 8 \times 8$: всего 8 разных значений важного параметра. В 6D — по 2 значения на ось. Если важна только одна ось, grid тратит бюджет на повторение одних и тех же её значений (Bergstra, Bengio, 2012). В коде урока при 9 запусках grid проверил 3 значения `gamma`, random — 9.

**Масштаб.** Гиперпараметры вроде `C`, `gamma`, learning rate, weight decay имеют смысл по порядку величины. Их сэмплируют **логравномерно** (`loguniform(1e-2, 1e2)`): равномерно по $\log$, иначе 99% точек окажется в $[1, 100]$.

### 3.2. Смещение отбора (optimism of the winner)

Пусть у $m$ кандидатов CV-оценки $\hat s_j = s_j + \varepsilon_j$, где $\varepsilon_j$ — шум оценки (урок 18). Выбираем $\hat j = \arg\max_j\hat s_j$. Тогда

$$\mathbb{E}\big[\hat s_{\hat j} - s_{\hat j}\big] > 0.$$

Максимум шумных оценок смещён вверх: мы выбираем того, кому повезло с шумом. Нагляднее всего крайний случай: все $m$ моделей одинаково хороши, $s_j = s$. Тогда $\hat s_{\hat j} = s + \max_j\varepsilon_j$, и при нормальном шуме $\mathbb{E}\max_j\varepsilon_j \approx \sigma\sqrt{2\ln m}$. Оценка «победителя» завышена, хотя все модели одинаковы. Чем больше кандидатов и меньше данных, тем сильнее завышение. Лечение — **вложенная CV** или отдельный test, к которому не прикасались при выборе. В коде: 143 комбинации на 150 объектах — невложенная оценка 0,960, вложенная 0,933.

### 3.3. Successive halving

$n$ кандидатов, бюджет $r$ (например, число объектов) на первом раунде. После каждого раунда остаётся $1/\eta$ лучших, бюджет каждого умножается на $\eta$. Общая стоимость раунда постоянна: $\frac{n}{\eta^k}\cdot r\eta^k = nr$. Раундов $\log_\eta n$, итого $O(nr\log_\eta n)$ против $O(n \cdot R)$ при полном бюджете $R$ для всех. Риск — «поздние цветы»: кандидат, плохой на малых данных, но лучший на больших, отсеивается рано.

## 4. Реализация с нуля

Файл: [код/tuning.py](код/tuning.py):

```python
def my_grid_search(estimator, grid, X, y, cv):
    results = []
    for values in itertools.product(*grid.values()):
        params = dict(zip(grid.keys(), values))
        model = clone(estimator).set_params(**params)
        results.append((cross_val_score(model, X, y, cv=cv).mean(), params))
    best_score, best_params = max(results, key=lambda r: r[0])
    return clone(estimator).set_params(**best_params).fit(X, y), best_params, best_score
```

`clone` создаёт «чистую» копию с теми же гиперпараметрами. Отсюда правило урока 34 про `__init__`. `set_params(svc__C=...)` обращается к параметру шага пайплайна через двойное подчёркивание. После выбора лучшая комбинация **переобучается на всех данных** (refit).

### Предсказание: что возвращают модели

| Метод | Что это | Когда |
|---|---|---|
| `predict(X)` | Метка / число | Финальный ответ при пороге по умолчанию |

## 6. Типичные ошибки и как их отлаживать

| Ошибка | Последствие | Как правильно |
|---|---|---|
| Подбор гиперпараметров по test | Оптимистичная оценка, модель «подогнана» под тест | CV на train для выбора; test — один раз; вложенная CV для честной оценки процедуры |
| Линейная сетка для `C`, `gamma`, lr | Бюджет уходит на один порядок величины | Логарифмическая сетка / `loguniform` |
| Grid по 6 параметрам × 5 значений | 15 625 запусков | Random search / Halving / Optuna |
| Лучшее значение на краю сетки | Оптимум, возможно, за пределами сетки | Расширить диапазон в эту сторону |
| Выбор по средней CV без учёта разброса | Выбор шума при разнице меньше погрешности | Смотреть `std_test_score`; правило «одной стандартной ошибки»: самая простая модель в пределах 1 SE от лучшей |
| Сохранить только модель без предобработки | Training-serving skew | Сохранять пайплайн целиком |
| `predict` для SVC без `probability=True` в коде, ждущем вероятности | Ошибка или неверный порог | `decision_function` или калибровка (урок 59) |

## Ответы на вопросы для самопроверки

1. Параметры выучиваются в `fit` из данных (веса, пороги дерева). Гиперпараметры задаются до обучения и выбираются внешней процедурой (C, глубина, learning rate).
2. При фиксированном бюджете random пробует больше различных значений каждого параметра, а важны обычно немногие. $P = 1 - (1 - 0{,}05)^n$, при $n = 60$ — ≈ 0,95.
3. Их влияние определяется порядком величины. Равномерная сетка тратит почти весь бюджет на верхний порядок диапазона.
4. Максимум шумных оценок смещён вверх: выбирается тот, кому повезло. Вложенная CV оценивает всю процедуру выбора на данных, не участвовавших в выборе (внешние фолды).
5. Много кандидатов на малом бюджете → отбросить худшие → оставшимся больше бюджета, и так по раундам. Риск — отсеять кандидата, который хорош только на большом бюджете.
6. Переобучает лучшую конфигурацию на всех переданных данных и кладёт результат в `best_estimator_`.
7. Предобработка — часть модели: без неё на инференсе другая нормализация и кодировка (training-serving skew). `joblib` использует pickle, загрузка которого может выполнить произвольный код.
