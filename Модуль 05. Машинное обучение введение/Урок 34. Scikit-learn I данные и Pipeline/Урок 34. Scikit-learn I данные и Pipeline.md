## 1. Зачем это нужно

scikit-learn — стандартный инструмент классического ML, а его API (`fit` / `transform` / `predict`) скопировали множество библиотек: XGBoost, LightGBM, CatBoost, обёртки для PyTorch (skorch). Понять его устройство — значит уметь:
- собрать пайплайн, который **физически не может** протечь: всё, что обучается, обучается только на train-части фолда;
- правильно разбить данные — со стратификацией для редких классов и по группам для кадров видео;
- сохранить предобработку вместе с моделью: training-serving skew из урока 1 исчезает, когда сохраняется весь пайплайн.

## 2. Интуиция: API оценщика

В scikit-learn всё — **оценщик (estimator)** с общим интерфейсом:
- `fit(X, y)` — выучить параметры по данным (среднее для скейлера, веса для модели). Выученное хранится в атрибутах с подчёркиванием на конце: `mean_`, `coef_`;
- `transform(X)` — у трансформеров: применить выученное к любым данным;
- `predict(X)` / `predict_proba(X)` — у моделей;
- `score(X, y)` — метрика по умолчанию.

Гиперпараметры передаются только в `__init__` и не меняются в `fit`. Благодаря этому `clone` и `GridSearchCV` могут создавать копии оценщика с другими параметрами.

**Pipeline** — цепочка «трансформер → трансформер → … → модель», которая сама ведёт себя как один оценщик. `fit` пайплайна обучает каждый шаг на выходе предыдущего. `predict` только применяет. Если положить пайплайн в `cross_val_score`, в каждом фолде всё переобучается на train-части — утечка невозможна.

**ColumnTransformer** — «разные колонки — разная предобработка»: категории в one-hot, час в $(\sin, \cos)$, числа — импутация и масштабирование. Результаты склеиваются.

## 3. Математика

### 3.1. Зачем стратификация: дисперсия доли класса в выборке

Без стратификации число положительных в test размера $m$ из датасета, где их $K$ из $N$, имеет гипергеометрическое распределение. Его дисперсия ≈ $m\,p(1-p)$, $p = K/N$ (урок 15). Для $p = 0{,}043$ и $m = 60$ стандартное отклонение доли — $\sqrt{p(1-p)/m} \approx 0{,}026$, сравнимо с самой долей. В коде урока доля в случайном test колебалась от 0 до ≈ 0,1, то есть бывают тесты **вообще без** редкого класса. На таком тесте recall редкого класса не посчитать.

Стратификация берёт из каждого класса одну и ту же долю, и дисперсия доли ≈ 0 (остаётся только округление: $\text{round}(0{,}2 \cdot 13) = 3$ из 60 даёт 0,05 вместо 0,043). Это частный случай **стратифицированной выборки** в статистике: если разбить совокупность на однородные слои и выбирать из каждого пропорционально, дисперсия оценки уменьшается.

### 3.2. Какой сплит выбрать

| Структура данных | Сплит | Почему |
|---|---|---|
| Независимые объекты, сбалансированные классы | `KFold` / `train_test_split` | Достаточно |
| Редкие классы | `StratifiedKFold` / `stratify=y` | Доли классов в каждом фолде (3.1) |
| Группы почти-копий (кадры видео, снимки пациента, одна сцена) | `GroupKFold`, `StratifiedGroupKFold`, `GroupShuffleSplit` | Иначе утечка (уроки 12, 27) |
| Время (данные из будущего недоступны) | `TimeSeriesSplit` / сплит по дате | Иначе утечка из будущего |

Общее правило: **сплит должен имитировать то, как модель будет применяться**. Новые камеры — групповой сплит по камерам. Новые дни — по времени.

### 3.3. Три выборки

- **train** — обучение;
- **validation** (или CV на train) — выбор модели и гиперпараметров (урок 35);
- **test** — **одна** финальная оценка.

Если выбирать по test, его оценка становится смещённой вверх: множественные сравнения, урок 18.

## 4. Реализация с нуля

Файл: [код/mini_sklearn.py](код/mini_sklearn.py):

```python
class MiniPipeline:
    def __init__(self, steps):
        self.steps = steps

    def fit(self, X, y=None):
        for _, step in self.steps[:-1]:
            X = step.fit_transform(X, y)
        self.steps[-1][1].fit(X, y)
        return self

    def _transform(self, X):
        for _, step in self.steps[:-1]:
            X = step.transform(X)
        return X

    def predict(self, X):
        return self.steps[-1][1].predict(self._transform(X))


class CyclicEncoder(TransformerMixin, BaseEstimator):
    def __init__(self, period: float = 24.0):
        self.period = period                       # параметры только сохраняются в __init__ — правило sklearn для clone/GridSearch

    def fit(self, X, y=None):
        self.n_features_in_ = np.asarray(X).shape[1]
        return self

    def transform(self, X):
        a = 2 * np.pi * np.asarray(X, float) / self.period
        return np.hstack([np.sin(a), np.cos(a)])
```

Наследование от `BaseEstimator` даёт `get_params`/`set_params`, а значит работу с `clone`, `GridSearchCV` и пайплайнами (тест `test_cyclic_encoder_is_sklearn_compatible` подбирает `period` через `GridSearchCV`). `TransformerMixin` даёт `fit_transform`.

Ещё в файле — свои `stratified_split` и `group_split`.

## 5. Сверка и полный поток

Файл: [код/workflow.py](код/workflow.py):

```
MiniPipeline 0.9722 | sklearn Pipeline 0.9722 | предсказания совпадают: True

доля редкого класса в test (истинная 0.043): без стратификации 0.045 ± 0.022 (min 0.000), со стратификацией 0.050 ± 0.000

Pipeline на сыром DataFrame: ROC-AUC 0.792 ± 0.006
признаки после ColumnTransformer: ['cat__camera_dock', 'cat__camera_gate', 'cat__camera_roof', 'cat__camera_yard', 'hour__hour_sin', 'hour__hour_cos', 'num__brightness', 'num__blur', 'num__missingindicator_brightness']

```

Главное — третий блок. `cross_val_score` получает **сырой DataFrame** с пропусками, строками-категориями и часами, а пайплайн в каждом фолде заново:
- обучает импутер, скейлер и one-hot на train-части;
- добавляет индикатор пропуска (урок 27);
- кодирует час циклически (урок 28);
- обучает модель.

`get_feature_names_out` показывает, какие признаки получила модель. Это важно для интерпретации весов и важностей.

Здесь `GroupKFold` по видео дал почти тот же ROC-AUC, что и стратифицированный (0,791 против 0,792): в синтетике кадры одного видео не похожи друг на друга. На настоящих видео разница бывает огромной (урок 27: 1,00 против 0,54). Поэтому групповой сплит нужен **по умолчанию**, если группы существуют.

## 6. Типичные ошибки и как их отлаживать

| Ошибка | Последствие | Как правильно |
|---|---|---|
| `fit_transform` всего датасета, потом сплит | Утечка | Всё обучаемое — шаги `Pipeline` |
| `fit` трансформера на test | Test нормирован своими статистиками | На test только `transform` / `predict` пайплайна |
| Сплит без `stratify` при редких классах | Тест без редкого класса, «скачущие» метрики | `stratify=y`, `StratifiedKFold` |
| Случайный сплит кадров видео | Завышенная метрика | `GroupKFold` по видео / сцене |
| Нет `random_state` | Невоспроизводимые сплиты и метрики | Фиксировать сиды (урок 2) |
| Свой трансформер меняет параметры в `fit` или хранит не все параметры из `__init__` | `clone` и `GridSearchCV` молча ломаются | Параметры — только присваивание в `__init__`; выученное — атрибуты с `_` |
| Колонки по номерам в `ColumnTransformer` | Ломается при смене порядка колонок | По именам колонок DataFrame |
| `OneHotEncoder` без `handle_unknown` | Падение на новой категории в продакшене | `handle_unknown="ignore"` или `"infrequent_if_exist"` |

## Ответы на вопросы для самопроверки

1. `fit` выучивает параметры (атрибуты с `_`), `transform` / `predict` применяют их, `score` — метрика. Гиперпараметры живут в `__init__` и не меняются в `fit`, чтобы `clone` / `get_params` / `set_params` создавали корректные копии для CV и поиска гиперпараметров.
2. Пайплайн обучается целиком внутри каждого фолда на train-части. Статистики трансформеров (среднее, медиана, словарь категорий, отобранные признаки) не видят валидационную часть.
3. Разные колонки требуют разной предобработки, а результат должен быть одной матрицей признаков. `get_feature_names_out()` у ColumnTransformer или у пайплайна без последнего шага (`model[:-1]`).
4. Число объектов класса в случайном тесте случайно (гипергеометрическое) с относительным разбросом $\sim\sqrt{(1-p)/(mp)}$. При $mp \approx 2{,}6$ вероятность нуля ≈ $e^{-2{,}6} \approx 7\%$.
5. Видео — групповой сплит по видео. Камеры — по камерам, если модель будет работать на новых камерах. Время — `TimeSeriesSplit` или разбиение по дате.
6. Train — обучение; validation — выбор моделей и гиперпараметров; test — одна несмещённая итоговая оценка. Выбор по test делает его оценку оптимистичной.
7. Наследовать `BaseEstimator` и `TransformerMixin`; в `__init__` только сохранять параметры под теми же именами; в `fit` вычислять атрибуты с `_` и возвращать `self`; реализовать `transform` (и по возможности `get_feature_names_out`).
