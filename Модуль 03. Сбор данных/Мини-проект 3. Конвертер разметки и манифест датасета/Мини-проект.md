**Модуль 3** · ≈ 4 ч · неделя 12 · пререквизиты: уроки 22, 25, 26
**Данные:** Pascal VOC 2007 ([host.robots.ox.ac.uk/pascal/VOC](http://host.robots.ox.ac.uk/pascal/VOC/) — архив `VOCtrainval_06-Nov-2007.tar`, ≈ 450 МБ, 5011 картинок, 20 классов). Альтернатива без скачивания с сайта VOC — `torchvision.datasets.VOCDetection(root, year="2007", download=True)`.

## Цель

Сделать инструмент, который понадобится в capstone и на работе: надёжный конвертер разметки между тремя форматами и **манифест** датасета — одну таблицу «картинка — объект — рамка» с метаданными, из которой дальше строятся EDA, сплиты и проверки качества.

## Техническое задание

### Часть 1. Конвертер (≈ 1,5 ч)

1. Возьми за основу `annotation_formats.py` из урока 26 и сделай из него пакет `labelconv/` с CLI:
   ```bash
   python -m labelconv voc2coco --src VOC2007/Annotations --images VOC2007/JPEGImages --out coco.json
   ```
   ```bash
   python -m labelconv coco2yolo --src coco.json --out yolo_labels/ --classes classes.txt
   ```
   ```bash
   python -m labelconv yolo2coco --src yolo_labels/ --images VOC2007/JPEGImages --classes classes.txt --out coco_back.json
   ```
2. Учти особенности VOC: 1-based координаты, флаги `difficult` и `truncated` (сохрани их в COCO как дополнительные поля, а при экспорте в YOLO — опция «пропускать difficult»).
3. Список классов — **один источник истины** (`classes.txt`), порядок фиксирован.
4. В `yolo2coco` размер картинки читается из файла (`PIL.Image.open(p).size` — без декодирования пикселей) и учитывает EXIF-ориентацию (урок 25).

### Часть 2. Манифест (≈ 1 ч)

1. Таблица `manifest`: `image_id`, `file_name`, `width`, `height`, `sha256` картинки, `split` (train/val из файлов `ImageSets/Main`), `ann_id`, `category`, `x1, y1, x2, y2`, `difficult`, `truncated`.
2. Сохрани в **Parquet** (типы: `category`, `float32`, `bool`) и в **SQLite** (две таблицы `images` и `annotations` с индексом по `image_id`).
3. Покажи, что Parquet читается обратно без потери типов (`pd.testing.assert_frame_equal`), а пять запросов из урока 25 работают на SQLite-версии.

### Часть 3. Валидатор (≈ 1 ч)

`validate(manifest) -> DataFrame` проблем со столбцами `image_id`, `ann_id`, `problem`:
- рамка выходит за кадр (с допуском 1 px) или вырождена;
- неизвестный класс (нет в `classes.txt`);
- картинка из разметки отсутствует на диске или не открывается;
- пустые файлы разметки и картинки без разметки;
- точные дубликаты рамок и почти-дубликаты (IoU > 0,95 одного класса на одной картинке — векторизованно, урок 21);
- одна и та же картинка (по `sha256`) в train и val — **утечка** (урок 12).

### Часть 4. Отчёт (≈ 0,5 ч)

Короткий `report.ipynb`: сколько проблем каждого типа нашлось в официальной разметке VOC 2007, примеры 3–5 проблемных картинок с рамками (урок 23), распределение классов по сплитам.

## Критерии готовности

- [ ] Round-trip VOC → COCO → YOLO → COCO → VOC сохраняет все рамки с точностью до пикселя (тест на всём VOC 2007: максимальная ошибка ≤ 1 px, число объектов совпадает).
- [ ] Валидатор покрыт pytest-тестами: на каждый тип проблемы — маленький вручную составленный пример, где проблема есть, и пример, где её нет.
- [ ] Parquet читается обратно без потери типов; SQLite-запросы из урока 25 работают.
- [ ] CLI работает из терминала; `--help` описывает все команды.
- [ ] Нет Python-циклов по объектам в валидаторе (цикл по файлам при чтении XML допустим).
