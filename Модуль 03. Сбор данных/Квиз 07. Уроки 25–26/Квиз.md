# Квиз 7. Уроки 25–26 (+ повторение модуля 2)

**30 минут, без интерпретатора.** Ответы — в конце под спойлером. Ошибки выпиши в [решения/ошибки.md](решения/).

---

1. Напиши SQL: число объектов каждого класса на картинках с камеры `cam_dock`, по убыванию.
2. Чем `LEFT JOIN ... WHERE right.id IS NULL` отличается от `INNER JOIN`? Какую задачу QA разметки он решает?
3. Как в SQL получить по одному самому уверенному объекту на картинку? Почему тут не хватает `GROUP BY image_id` с `MAX(score)`?
4. Запрос `WHERE image_id = ?` выполняется 500 раз и работает медленно. Что показывает `EXPLAIN QUERY PLAN` и что сделать?
5. API вернул 404, затем 503, затем таймаут соединения. Какие из этих ошибок клиент должен повторить?
6. Фото с телефона после загрузки через `np.asarray(Image.open(p))` повёрнуто на 90°, а рамки — нет. Что произошло и как исправить?
7. Запиши YOLO-строку для рамки xyxy = (100, 50, 300, 250) класса 2 на картинке 400×500 (ширина × высота).
8. Та же рамка в Pascal VOC (`xmin ymin xmax ymax`)?
9. Почему маски сегментации хранят в PNG, а фото — в JPEG?
10. *(урок 22)* Таблицу аннотаций прочитали из CSV, и merge с таблицей картинок по `image_id` дал 0 совпадений. Назови самую вероятную причину.

---

<details>
<summary><b>Ответы</b></summary>

1. `SELECT c.name, COUNT(*) AS n FROM annotations a JOIN categories c ON c.id = a.category_id JOIN images i ON i.id = a.image_id WHERE i.camera = 'cam_dock' GROUP BY c.name ORDER BY n DESC;`
2. `INNER JOIN` оставляет только строки с парой. `LEFT JOIN` сохраняет все строки слева, у строк без пары справа — NULL, и фильтр `IS NULL` оставляет **только** строки без пары. Это анти-JOIN: картинки без разметки, классы без примеров.
3. `ROW_NUMBER() OVER (PARTITION BY image_id ORDER BY score DESC)` в CTE и `WHERE rnk = 1`. `GROUP BY` + `MAX(score)` даёт значение максимума, но не остальные колонки **той же строки** (id объекта, координаты). Чтобы их достать, понадобился бы повторный JOIN.
4. `SCAN annotations` — полный просмотр таблицы. Нужен индекс: `CREATE INDEX ... ON annotations(image_id)`, после этого план — `SEARCH ... USING INDEX`, поиск за $O(\log n)$.
5. Повторить 503 и таймаут (временные проблемы) с экспоненциальной задержкой и джиттером. 404 не повторять: ресурс не существует.
6. Телефон сохранил пиксели в ориентации сенсора, а поворот записан в EXIF `Orientation`. Разметчик видел повёрнутую картинку. Исправление — `ImageOps.exif_transpose` при загрузке, одинаково при обучении и инференсе.
7. Центр $(200, 150)$, размер $200 \times 200$. Нормируем на $W = 400$, $H = 500$: `2 0.5 0.3 0.5 0.4`.
8. Пиксели с 1, `xmax` включительно: `xmin = 101, ymin = 51, xmax = 300, ymax = 250`.
9. Маска — резкие границы и точные значения классов: JPEG искажает границы и может создать несуществующие классы. PNG сжимает без потерь, а кусочно-постоянные картинки — ещё и очень компактно. Фото без потерь сжимается плохо (высокая энтропия шума), а JPEG даёт в разы меньший размер при незаметных глазу искажениях.
10. Разные типы ключа: в CSV `image_id` вида `"000123"` прочитался как число 123, а в таблице картинок он строка (или наоборот). Нужно привести типы до merge, а лучше хранить таблицы в Parquet.

</details>
