## Самопроверка (30 минут)

1. Есть таблицы `images(id, camera)` и `annotations(id, image_id, category_id, score)`. Напиши запрос: для каждой камеры — доля картинок, где **все** объекты имеют уверенность > 0,8 (картинки без объектов не считаем).
2. Твой загрузчик датасета через API иногда падает в середине ночи и начинает всё заново. Что добавить в код?
3. Подрядчик прислал разметку в YOLO и папку картинок. Чего не хватает для перевода в COCO, и где это взять?
4. Почему рамки, переведённые из VOC «наивно» (без поправки), дают систематически заниженный IoU с правильными?
5. Где хранить манифест датасета из 10 млн объектов, к которому делают аналитические запросы по нескольким колонкам, — CSV, JSON, Parquet или SQLite? Обоснуй.

<details>
<summary>Ответы</summary>

1. ```sql
   WITH per_image AS (
       SELECT i.camera, a.image_id, MIN(a.score) AS min_score
       FROM annotations a JOIN images i ON i.id = a.image_id
       GROUP BY i.camera, a.image_id)
   SELECT camera, AVG(CASE WHEN min_score > 0.8 THEN 1.0 ELSE 0.0 END) AS share
   FROM per_image GROUP BY camera;
   ```
   «Все объекты > 0,8» ⇔ «минимальная уверенность > 0,8».
2. Повторы временных ошибок с backoff; таймауты; докачку — сохранять прогресс (кэш ответов или манифест скачанного) и при перезапуске пропускать уже полученное. Плюс логирование ошибок вместо падения на первой.
3. Размеров картинок (YOLO хранит доли кадра) и имён классов (YOLO хранит индексы). Размеры — из самих файлов (`PIL.Image.open(p).size` с учётом EXIF), имена — из `data.yaml` / `classes.txt` подрядчика.
4. Каждая рамка сдвинута на 1 px влево-вверх относительно правильной. Перекрытие уменьшается, и для маленьких объектов (10×10 px) IoU падает заметно: с 1,0 до ≈ 0,68.
5. Parquet (или колоночная БД, если нужен многопользовательский доступ): колоночное чтение только нужных полей, сжатие в разы, сохранность типов, pushdown фильтров. CSV и JSON большие и теряют типы. SQLite хороша для точечных запросов по индексу и небольших объёмов, но аналитические сканы по 10 млн строк в колоночном формате быстрее.
