## 1. Зачем это нужно

Конвертация данных между форматами — ежедневная задача CV-инженера:
- разметка из CVAT в COCO, а Ultralytics ждёт YOLO txt;
- старый датасет в Pascal VOC XML;
- метрики — в CSV для менеджера и в Parquet для анализа;
- маски сегментации — PNG.

Каждый переход — место для тихой ошибки:
- ведущие нули в id картинок исчезли в CSV;
- рамки VOC «уехали» на пиксель из-за 1-based координат;
- маска, сохранённая в JPEG, получила классы, которых не существует;
- чужой `.pkl` выполнил произвольный код.

## 2. Интуиция

**Табличные форматы** делятся на две семьи:
- **текстовые построчные** (CSV, JSON Lines): читаются человеком и любой программой, но всё хранится как текст — типы теряются и угадываются заново, файлы большие, а чтобы прочитать одну колонку, нужно прочитать всё;
- **бинарные колоночные** (Parquet, Feather/Arrow): каждая колонка хранится отдельно и сжата, типы записаны в схему, можно читать только нужные колонки и пропускать ненужные блоки строк.

**Excel** — для людей, не для пайплайнов. **Pickle** — сериализация Python-объектов, удобная, но **опасная**: при загрузке может выполниться произвольный код.

**Форматы разметки CV** различаются тремя вещами:
1. один файл на датасет или файл на картинку;
2. как задана рамка — углы или центр и размер;
3. в пикселях или долях кадра, и откуда считаются пиксели — с 0 или с 1.

| | Pascal VOC | COCO | YOLO |
|---|---|---|---|
| Файл | XML на картинку | Один JSON на сплит | TXT на картинку |
| Рамка | `xmin ymin xmax ymax` | `[x, y, w, h]` (левый верхний угол + размер) | `class cx cy w h` (центр + размер) |
| Единицы | Пиксели, **с 1, включительно** | Пиксели, непрерывные | **Доли** кадра $[0, 1]$ |
| Класс | Имя строкой | `category_id` + таблица категорий | Индекс в списке классов (`data.yaml`) |
| Размер картинки | В XML | В `images` | **Не хранится** — нужно читать картинку |
| Сегментация | Отдельные PNG-маски | Полигоны или RLE в JSON | Полигоны в нормированных координатах |

## 3. Математика

### 3.1. Сжатие и энтропия

Нижняя граница длины кода без потерь — энтропия источника (урок 15): в среднем нельзя тратить меньше $H(X)$ бит на символ. Отсюда три следствия.
- **Колонка сжимается лучше строки.** Значения одной колонки однородны (все `category` — 4 слова, все `x` — float в узком диапазоне), их энтропия ниже, чем у вперемешку записанных разных полей. Поэтому Parquet в 2,3 раза меньше CSV и в 4,6 раза меньше JSON.
- **Словарное кодирование** колонки `category`: вместо строки храним индекс в словаре из 4 значений, то есть $\le\log_2 4 = 2$ бита до сжатия. Это то же, что dtype `category` в pandas (урок 22).
- **Фото не сжать без потерь сильно**: у сенсорного шума высокая энтропия. PNG фото — 491 КБ при 820 КБ сырых. **Сжатие с потерями** (JPEG, WebP) выбрасывает то, что глаз плохо видит. JPEG делит картинку на блоки 8×8, раскладывает каждый по косинусам (DCT) и грубо квантует высокие частоты.

### 3.2. Почему JPEG портит маски

Маска сегментации — кусочно-постоянная картинка с резкими границами. Резкая граница — это **высокие частоты**, именно их JPEG огрубляет. На границах появляются промежуточные значения («звон»). Для фото это незаметно. Для маски значение 1 рядом с 2 превращается в 1,4 → после округления 1 или 2, а иногда появляется **несуществующий класс**. В коде урока при quality=75 появилось 4-е значение, а 0,88% пикселей получили неверный класс. **Маски — только PNG** (или NPY/RLE).

### 3.3. Predicate pushdown в Parquet

Parquet делит таблицу на **группы строк** (row groups). В метаданных каждой группы для каждой колонки записаны min и max. Запрос «`captured_at` ≥ 29 октября» сначала смотрит метаданные и **не читает** группы, где max < 29 октября. Если данные отсортированы по колонке фильтра, читается доля $\approx$ (доля подходящих строк) от файла. Плюс читаются только запрошенные колонки. Это колоночная проекция.

### 3.4. Арифметика координат

Между форматами рамку переводят линейными формулами:

$$\text{COCO} \to \text{xyxy}: (x, y, w, h) \mapsto (x, y, x + w, y + h);\qquad \text{xyxy} \to \text{YOLO}: \Big(\tfrac{x_1 + x_2}{2W}, \tfrac{y_1 + y_2}{2H}, \tfrac{x_2 - x_1}{W}, \tfrac{y_2 - y_1}{H}\Big).$$

**VOC:** пиксели нумеруются с 1, а `xmax` включителен. Рамка «весь кадр 500 пикселей» записана как `xmin=1, xmax=500`. В непрерывных координатах это $[0, 500)$, поэтому $x_1 = \text{xmin} - 1$, $x_2 = \text{xmax}$. Если про это забыть, каждая рамка VOC сдвинется на 1 пиксель влево-вверх. Для мелких объектов это заметная потеря IoU.

### 4.1. Конвертеры разметки с нуля

Файл: [код/annotation_formats.py](код/annotation_formats.py). Все форматы сводятся к одному **внутреннему представлению** — пиксельные xyxy в непрерывных координатах. Тогда нужно $2k$ конвертеров («в» и «из» каждого формата), а не $k(k-1)$ (каждый в каждый):

```python
def to_yolo(img: ImageAnns, categories: list[str]) -> str:

        cx, cy = (a.x1 + a.x2) / 2 / img.width, (a.y1 + a.y2) / 2 / img.height
        w, h = (a.x2 - a.x1) / img.width, (a.y2 - a.y1) / img.height
        lines.append(f"{categories.index(a.label)} {cx:.6f} {cy:.6f} {w:.6f} {h:.6f}")
```

Что видно:
- **CSV и JSON теряют типы.** `"025518"` превратился в число 25518: id картинки больше не совпадёт с именем файла `025518.jpg`. Категория стала строкой, дата — строкой. Лечение — явные `dtype=` и `parse_dates=` при чтении, но проще не хранить таблицы в CSV.
- **Parquet и Feather** сохранили всё и в 2,3–5 раз меньше. Feather — самый быстрый: он почти без сжатия и почти совпадает с представлением Arrow в памяти. Подходит для промежуточных файлов. Parquet — для хранения и обмена: лучшее сжатие, статистики, pushdown.
- **Excel** не умеет даты с часовым поясом — запись падает с `ValueError`. Это поймал первый запуск кода. Пришлось отбросить tz, то есть потерять информацию.
- **Pickle** быстрый и сохраняет всё, но последняя строка вывода — код, который выполнился **просто при загрузке** файла. Чужие `.pkl` (и веса моделей в старом формате `torch.load` без `weights_only=True`) — это исполнение чужого кода.

## 5. Другие форматы, которые встретятся

| Формат | Что это | Когда |
|---|---|---|
| **Feather / Arrow IPC** | Колоночный, почти без сжатия, мгновенное чтение | Промежуточные файлы, обмен между процессами |
| **HDF5** (`h5py`) | Иерархический контейнер массивов с частичным чтением | Большие массивы признаков, старые датасеты |
| **NPY / NPZ** | Массив NumPy (+ zip архив массивов) | Эмбеддинги, карты глубины, кэш признаков |
| **Pickle** | Сериализация Python-объектов | Только свои, только временно; никогда — чужие |
| **safetensors** | Безопасное хранение весов моделей (без исполнения кода) | Веса моделей, Hugging Face |
| **ONNX** | Граф модели для инференса | Деплой (capstone, КП-5) |
| **WebDataset (tar-шарды), TFRecord** | Потоковые шарды «картинка + разметка» | Обучение на больших датасетах без миллионов мелких файлов |
| **MP4/H.264, MKV** | Видео с межкадровым сжатием | Видео с камер; кадры извлекать с учётом сжатия (артефакты на движении) |
| **RLE (COCO)** | Сжатие масок «длинами серий» | Маски в COCO JSON |

## 6. Типичные ошибки и как их отлаживать

| Ошибка | Последствие | Как правильно |
|---|---|---|
| id и коды в CSV без `dtype=str` | Ведущие нули потеряны, соединение с файлами ломается | Parquet; или `dtype` при чтении CSV |
| `sep`, кавычки, кодировка CSV | Сдвиг колонок из-за `;` или `,` в тексте; кракозябры из-за cp1251 | Явные `sep`, `quotechar`, `encoding="utf-8"` |
| VOC без учёта 1-based | Все рамки сдвинуты на 1 px | Конвертер с явным правилом и тестом «рамка на весь кадр» |
| YOLO без размера картинки | Невозможно вернуться к пикселям | Хранить размеры в манифесте (мини-проект 3) |
| Порядок классов YOLO не совпадает с `data.yaml` | Модель учится называть машины людьми | Один источник истины для списка классов |
| Маски в JPEG | Шум на границах и несуществующие классы | PNG |
| Чужой pickle / `torch.load` без `weights_only=True` | Исполнение произвольного кода | safetensors, `weights_only=True`, Parquet/NPY |
| Даты без часового пояса | Сдвиги на часы при соединении источников | UTC в хранилище; Excel — только для отчётов |

## Ответы на вопросы для самопроверки

1. Для запроса нужны лишь некоторые колонки — их и читаем. Однородные значения одной колонки имеют низкую энтропию и хорошо сжимаются (плюс словарное кодирование для повторяющихся строк).
2. Пропуск групп строк, у которых по min/max-статистикам в метаданных заведомо нет подходящих строк. Эффективен, когда данные отсортированы (или сгруппированы) по колонке фильтра.
3. CSV — текст без схемы, типы при чтении угадываются заново. Примеры: id `"000123"` → число 123, и связь с `000123.jpg` потеряна; категория → строка, время с часовым поясом → строка или наивное время; список полигонов → строка `"[1, 2, ...]"`.
4. VOC — углы в пикселях (1-based, включительно); COCO — левый верхний угол + размер в пикселях; YOLO — центр + размер в долях кадра. Чтобы вернуться к пикселям, нужны ширина и высота, а в YOLO-файле их нет.
5. Пиксели нумеруются с 1, `xmax` включителен: непрерывные координаты — `[xmin - 1, xmax)`. Без поправки — сдвиг на 1 px.
6. Резкие границы — высокие частоты, которые JPEG квантует грубо. Возникают промежуточные значения и, после округления, неверные или несуществующие классы на границах.
7. Загрузка pickle может выполнить произвольный код (`__reduce__`). Для весов — safetensors или `torch.load(..., weights_only=True)`; для таблиц — Parquet; для массивов — NPY.
