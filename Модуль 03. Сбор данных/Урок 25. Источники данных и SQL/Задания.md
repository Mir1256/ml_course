**🟢 Базовое — «10 запросов к базе разметки»** (`queries.sql` + `test_queries.py`)
На базе `build_db()` из урока напиши SQL-запросы (каждый проверь против pandas-версии в тесте):
1. Число картинок и объектов по камерам.
2. Среднее число объектов на картинку по камерам (учти картинки без объектов — LEFT JOIN!).
3. Классы, у которых медианная уверенность ниже 0,7 (подсказка: в SQLite нет `MEDIAN` — посчитай через оконную функцию `ROW_NUMBER` и `COUNT(*) OVER`).
4. Разметчик с наибольшей долей объектов с уверенностью < 0,5.
5. Для каждой картинки — объект с максимальной площадью (оконная функция).
6. Картинки, где есть и `forklift`, и `person` (два способа: `INTERSECT` и `GROUP BY ... HAVING`).
7. По дням: число объектов и разница с предыдущим днём (`LAG`).
8. Скользящее среднее числа объектов за 7 дней (`AVG(...) OVER (ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)`).
9. Пары объектов одной картинки с IoU > 0,7 — кандидаты в дубли разметки (self-JOIN + формула IoU в SQL).
10. Доля картинок без каски при наличии человека — по камерам.

**🟡 Среднее — «Сбор метаданных съёмки»** (`weather_join.py` + `test_weather_join.py`)
1. Через `get_json` из урока скачай почасовую историю погоды Open-Meteo (archive API — найди эндпоинт в их документации) для координат склада за октябрь 2026: температура, облачность, осадки, `is_day`.
2. Сохрани в SQLite-таблицу `weather` (время в UTC, ISO-строкой).
3. Соедини с `images.captured_at` с точностью до часа — в SQL и в pandas (`pd.merge_asof`). Объясни, когда нужен `merge_asof`, а не обычный merge.
4. Посчитай среднюю уверенность модели по корзинам облачности и `is_day`.
5. Тесты — на локальном фейковом сервере, как в `test_sources.py` (сеть в тестах не используется).

**🔴 Со звёздочкой — «Вежливый краулер датасета»** (`crawler.py` + `test_crawler.py`)
Напиши асинхронный загрузчик картинок по списку URL (`asyncio` + `httpx` или `aiohttp`):
1. Ограничение параллелизма (`asyncio.Semaphore`), глобальный лимит частоты на домен (token bucket), уважение `Crawl-delay` и `Disallow` из robots.txt.
2. Повторы с backoff, таймауты, докачка: уже скачанное не качается повторно (проверка по SHA-256 содержимого).
3. Валидация: файл открывается Pillow, размер ≥ 64×64, применяется `exif_transpose`, сохраняется в PNG или JPEG с исходным качеством.
4. Манифест в Parquet: url, sha256, путь, ширина, высота, статус, ошибка.
5. Тесты — на локальном сервере с медленными, битыми и запрещёнными ответами. Проверь, что одновременно выполняется не больше N запросов и пауза для домена соблюдается.
